# Elements

`LYNX_ELEMENTS` declares every Lynx [element](/guide/glossary#element) as an Angular directive, so your templates type-check. `import { LYNX_ELEMENTS } from '@blotch/angular-lynx';`

## Usage

```typescript title="src/app/greeting.ts"
import { Component, signal } from '@angular/core';
import { LYNX_ELEMENTS } from '@blotch/angular-lynx';

@Component({
  selector: 'app-greeting',
  imports: [LYNX_ELEMENTS],
  template: `
    <view class="card">
      <image [src]="avatar()" />
      <text>Hello from Lynx</text>
    </view>
  `,
})
export class Greeting {
  readonly avatar = signal('https://example.com/avatar.png');
}
```

- **When it's needed:** your editor's type checking and `ng test` need it. `ng build` and `ng serve` add `CUSTOM_ELEMENTS_SCHEMA` for you, so they pass without it.
- **Attributes:** each directive declares its element's attributes as inputs, so `[src]="url()"` type-checks. Bind any other attribute with `[attr.name]`.
- **Events** aren't declared as outputs. Bind them by name, such as `(bindtap)`. See [Handling taps and events](/guide/elements/event-handling).

### `LynxIf` and `LynxFor`

```typescript
@Directive({ selector: 'if' })
class LynxIf {}

@Directive({ selector: 'for' })
class LynxFor {}
```

Declare Lynx's own low-level `<if>` and `<for>` elements, so a template that contains them type-checks. They're unrelated to Angular's `@if` and `@for` blocks, and AngularLynx doesn't test them. Use `@if` and `@for` instead.

### Attributes on every element

Every directive above, except the two form accessors and `LynxRouterLinkActive`, also accepts these inputs. Write the true/false ones either way, `flatten="false"` or `[flatten]="false"`; both give Lynx a boolean. The same goes for the numbers of `pan-intercept-direction` and `pan-intercept-scope`.

| Attribute                         | Type                 | Description                                                                           |
| --------------------------------- | -------------------- | ------------------------------------------------------------------------------------- |
| `id`                              | `string`             | Element ID. Selector queries find elements by it.                                     |
| `name`                            | `string`             | A name some Lynx APIs use to find the element.                                        |
| `user-interaction-enabled`        | `boolean`            | Whether the element receives touch events. Default `true`.                            |
| `native-interaction-enabled`      | `boolean`            | Whether the element receives the platform's own gestures.                             |
| `event-through`                   | `boolean`            | Lets touches pass through to the elements below.                                      |
| `hit-slop`                        | `string \| object`   | Extends the touch area beyond the element's box.                                      |
| `block-native-event`              | `boolean`            | Whether the element consumes native iOS and Android gestures.                         |
| `ignore-focus`                    | `boolean`            | Stops the element from taking focus.                                                  |
| `ios-enable-simultaneous-touch`   | `boolean`            | Lets iOS recognize this touch together with others.                                   |
| `flatten`                         | `boolean`            | Android only. `false` gives the element its own native view. Default `true`.          |
| `pan-intercept-direction`         | `0 \| 1`             | Takes pan gestures from views outside Lynx in this direction: horizontal or vertical. |
| `pan-intercept-scope`             | `0`–`5`              | Which outside views `pan-intercept-direction` takes pans from.                        |
| `consume-slide-event`             | `[number, number][]` | Swipe angle ranges the element keeps from platform gestures.                          |
| `enable-touch-pseudo-propagation` | `boolean`            | Lets `:active` also apply to ancestors.                                               |
| `accessibility-*`, `a11y-id`      |                      | See [Accessibility](/api/angular-lynx/accessibility#attributes).                      |
| `exposure-*`                      |                      | See [Exposure](/api/angular-lynx/exposure#attributes).                                |

### `LYNX_FORM_ACCESSORS`

```typescript
const LYNX_FORM_ACCESSORS: readonly [
  typeof LynxInputValueAccessor,
  typeof LynxTextareaValueAccessor,
];
```

Both form value accessors as one array. `LYNX_ELEMENTS` already contains them.

### `LynxInputValueAccessor` and `LynxTextareaValueAccessor`

```typescript
@Directive({
  selector:
    'input[formControlName], input[formControl], input[ngModel], input[formField]',
})
class LynxInputValueAccessor implements ControlValueAccessor {}

@Directive({
  selector:
    'textarea[formControlName], textarea[formControl], textarea[ngModel], textarea[formField]',
})
class LynxTextareaValueAccessor implements ControlValueAccessor {}
```

Connect `<input>` and `<textarea>` to reactive forms, `ngModel` and Signal Forms' `[formField]`. They switch on only when one of those form directives is on the element. Angular forms calls their members; you don't. Both classes have the same members.

### `onInput()`

```typescript
onInput(event: Event): void;
```

Runs on `bindinput`. Sends the typed text, `event.detail.value`, to the form control.

### `onBlur()`

```typescript
onBlur(): void;
```

Runs on `bindblur`. Marks the control as touched.

### `writeValue()`

```typescript
writeValue(value: string): void;
```

Shows the form value in the field through the element's `setValue` [UI method](/guide/glossary#ui-method). Lynx ignores changes to the `value` attribute after the user has typed, so `form.reset()` and `setValue()` need this.

### `registerOnChange()` and `registerOnTouched()`

```typescript
registerOnChange(fn: (value: string) => void): void;
registerOnTouched(fn: () => void): void;
```

Store the callbacks Angular forms passes in.

### `setDisabledState()`

```typescript
setDisabledState(isDisabled: boolean): void;
```

Sets or removes the element's `disabled` attribute.

## Types

None of its own. `ControlValueAccessor` comes from `@angular/forms`.
