# LynxNativeModule

Call native code that the host app exposes, and share JavaScript modules within a page. `import { LynxNativeModule, type NativeModuleMap } from '@blotch/angular-lynx';`

A **native module** is an object that the [host app](/guide/glossary#host-app) (the native iOS or Android app that runs your bundle) registers, with methods written in Swift, Kotlin or another native language.

## Usage

```typescript title="src/app/home.ts"
import { Component, inject } from '@angular/core';
import { LYNX_ELEMENTS, LynxNativeModule } from '@blotch/angular-lynx';

@Component({
  selector: 'app-home',
  imports: [LYNX_ELEMENTS],
  template: `<text>Home</text>`,
})
export class Home {
  readonly #native = inject(LynxNativeModule);

  constructor() {
    // Tell the host app that this screen opened.
    void this.#native.call('trackScreen', { name: 'home' });
  }
}
```

## API

### `LynxNativeModule`

```typescript
@Injectable({ providedIn: 'root' })
class LynxNativeModule {}
```

Typed access to Lynx's native module bridge and its JavaScript module registry. Every method is safe to call outside Lynx: it does nothing, or returns `undefined`.

:::info Calls run on the background thread
Lynx provides native modules and the module registry only on the [background thread](/guide/glossary#background-thread), and your app runs on the main thread. So every method sends its call there for you:

- **Results are copied as JSON**, and arrive as a promise.
- **Callbacks you pass,** such as a listener or a native method's callback, are called back on the main thread with their arguments copied as JSON. Setting a signal in one updates the screen.
- **A module is a stand-in.** `getNativeModule()` and `getJSModule()` return an object whose methods each run on the background thread and return a promise of the result.

See [Threads](/guide/concepts/threads).
:::

### `LynxNativeModule.call()`

```typescript
call<T = unknown>(name: string, params?: Record<string, unknown>): Promise<T | undefined>;
```

Calls the host's bridge method `name` with `params`, which defaults to `{}`. Resolves with the first value the host passes back, or `undefined` when there is no bridge.

### `LynxNativeModule.on()`

```typescript
on(name: string, callback: (...args: unknown[]) => void): void;
```

Listens for the bridge event `name` from the host. `callback` gets the event's arguments, copied as JSON. There's no way to stop listening.

### `LynxNativeModule.getNativeModule()`

```typescript
getNativeModule<K extends string>(
  name: K,
): K extends keyof NativeModuleMap ? NativeModuleMap[K] : unknown;
```

Returns a stand-in for the native module the host registered as `name`, or `undefined` outside Lynx. Each method you call on it runs on the background thread and returns a promise of the method's return value. The promise rejects if the host has no such module or method.

The return type comes from `NativeModuleMap`. Until you can extend that type (see below), cast the result to your module's interface.

### `LynxNativeModule.getJSModule()`

```typescript
getJSModule<T = unknown>(name: string): T | undefined;
```

Returns a stand-in for a JavaScript module registered in this page, such as Lynx's `GlobalEventEmitter` or one from `registerJSModule()`, or `undefined` outside Lynx. Like `getNativeModule()`, its methods return promises, and reject if the module isn't registered.

### `LynxNativeModule.registerJSModule()`

```typescript
registerJSModule<T extends object>(name: string, module: T): void;
```

Registers `module` under `name`, so other code in this page, including native callbacks, can find it. The background thread registers a copy: its methods, including ones on `module`'s class, call yours on the main thread with their arguments copied as JSON, and their return values are dropped. Its other fields are copied once.

## Types

### `NativeModuleMap`

```typescript
type NativeModuleMap = {};
```

Maps module names to their types for `getNativeModule()`. It's meant to be extended with your own modules, but it's declared as a `type`, which TypeScript can't merge with your declarations. Cast instead:

```typescript title="src/app/battery.ts"
import { Injectable, inject } from '@angular/core';
import { LynxNativeModule } from '@blotch/angular-lynx';

type DeviceModule = {
  getBatteryLevel(callback: (level: number) => void): void;
};

@Injectable({ providedIn: 'root' })
export class Battery {
  readonly #device = inject(LynxNativeModule).getNativeModule(
    'DeviceModule',
  ) as DeviceModule | undefined;

  read(callback: (level: number) => void): void {
    this.#device?.getBatteryLevel(callback);
  }
}
```
