# LynxTheme

The device's light or dark appearance, and on Android its wallpaper's colors, as signals. `import { LynxTheme } from '@blotch/angular-lynx';`

## Usage

```typescript title="src/app/app.ts"
import { Component, inject } from '@angular/core';
import { LYNX_ELEMENTS, LynxTheme } from '@blotch/angular-lynx';

@Component({
  selector: 'app-root',
  imports: [LYNX_ELEMENTS],
  template: `
    <view [class.dark]="theme.isDarkMode()">
      <text>The theme is {{ theme.theme() }}</text>
    </view>
  `,
})
export class App {
  readonly theme = inject(LynxTheme);
}
```

## API

### `LynxTheme`

```typescript
@Injectable({ providedIn: 'root' })
class LynxTheme {}
```

Reads the `theme` value that the [host app](/guide/glossary#host-app) sets in its global data. The host usually sets it from the operating system's appearance setting.

### `LynxTheme.theme`

```typescript
readonly theme: Signal<'Light' | 'Dark'>;
```

The current theme. `'Light'` when the host sets none.

### `LynxTheme.isDarkMode`

```typescript
readonly isDarkMode: Signal<boolean>;
```

`true` when `theme()` is `'Dark'`.

### `LynxTheme.dynamicColors`

```typescript
readonly dynamicColors: Signal<DynamicColors | null>;
```

The colors Android 12 and later take from the user's wallpaper (Material You's **dynamic color**), as [Material 3's color roles](https://m3.material.io/styles/color/roles), in a light and a dark scheme. `null` where the host app sends none.

```typescript
const theme = inject(LynxTheme);

// The wallpaper's tertiary color, or your own where there's none.
const accent = computed(
  () => theme.dynamicColors()?.light.tertiary ?? '#7d5260',
);
```

- **It comes from the host app,** in its `dynamicColors` GlobalData value: `{ light, dark }`, each with a hex color, such as `#6750a4`, for every role in `DYNAMIC_COLOR_ROLES`. A scheme with a role missing counts as none.
- **The Android app [`ng build --platform android`](/guide/building-for-production) builds sends it**, and sends it again when the user changes their wallpaper or colors. iOS, the web preview and Lynx Explorer have none.
- **Both schemes come at once,** so an app that keeps its own light or dark theme can use the right one.
- **To color the UI components with it,** use [Dynamic Color](/dolan/dynamic-color).

## Types

### `DynamicColors`

```typescript
type DynamicColors = {
  readonly light: DynamicColorScheme;
  readonly dark: DynamicColorScheme;
};
```

### `DynamicColorScheme`

```typescript
type DynamicColorScheme = { readonly [R in DynamicColorRole]: string };
```

Each role's color, as a hex color such as `#6750a4`.

### `DynamicColorRole`

One of Material's color roles, as `DYNAMIC_COLOR_ROLES` lists them:

- `primary`, `onPrimary`, `primaryContainer`, `onPrimaryContainer`, `inversePrimary`
- `secondary`, `onSecondary`, `secondaryContainer`, `onSecondaryContainer`
- `tertiary`, `onTertiary`, `tertiaryContainer`, `onTertiaryContainer`
- `background`, `onBackground`, `surface`, `onSurface`, `surfaceVariant`, `onSurfaceVariant`
- `surfaceDim`, `surfaceBright`, `surfaceContainerLowest`, `surfaceContainerLow`, `surfaceContainer`, `surfaceContainerHigh`, `surfaceContainerHighest`
- `inverseSurface`, `inverseOnSurface`, `outline`, `outlineVariant`

The error roles aren't there: Material keeps errors red whatever the wallpaper.
