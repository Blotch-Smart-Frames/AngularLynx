# `<canvas>`

A drawing surface with a 2D or WebGL2 context: charts, signatures, image editing and anything else drawn with [`getContext('2d')`](https://developer.mozilla.org/en-US/docs/Web/API/CanvasRenderingContext2D), and 3D scenes with [three.js](https://threejs.org/), [angular-three](https://github.com/angular-threejs/angular-three) or plain [WebGL](https://developer.mozilla.org/en-US/docs/Web/API/WebGL_API). Lynx has no canvas of its own: this one is AngularLynx's.

## Where it works

| Where                                                                                   | `getContext('2d')`                                                    | `getContext('webgl2')`                                                                                                    |
| --------------------------------------------------------------------------------------- | --------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| iOS apps built with [`ng build --platform ios`](/guide/building-for-production)         | Draws with Core Graphics, as Safari's canvas long did                 | Draws with OpenGL ES 3.0 on Metal, through [ANGLE](https://chromium.googlesource.com/angle/angle), as Safari's WebGL does |
| Android apps built with [`ng build --platform android`](/guide/building-for-production) | Draws with `android.graphics.Canvas`, which is Skia, as Chrome's does | Draws with the phone's OpenGL ES 3.0                                                                                      |
| The web preview                                                                         | The browser's canvas: the element is an HTML `<canvas>`               | The browser's WebGL2                                                                                                      |
| Lynx Explorer, and native apps that embed Lynx themselves                               | `null`: the canvas is an empty view                                   | `null`. Their apps don't have the canvas element                                                                          |

## Drawing in 2D

Give the canvas a size with CSS, size its drawing buffer to the screen's pixels once it's laid out, and draw:

```typescript title="src/app/chart.ts"
import {
  afterNextRender,
  Component,
  type ElementRef,
  viewChild,
} from '@angular/core';
import { LYNX_ELEMENTS, type LynxCanvasElement } from '@blotch/angular-lynx';

@Component({
  selector: 'app-chart',
  imports: [LYNX_ELEMENTS],
  template: `<canvas #canvas class="h-[200px] w-full"></canvas>`,
})
export class Chart {
  readonly canvas = viewChild.required<ElementRef<LynxCanvasElement>>('canvas');

  constructor() {
    afterNextRender(() => {
      const canvas = this.canvas()
        .nativeElement as unknown as HTMLCanvasElement;
      const context = canvas.getContext('2d')!;
      new ResizeObserver(([entry]) => {
        const { width, height } = entry.contentRect;
        // Setting the size clears the canvas and resets its state.
        canvas.width = width * devicePixelRatio;
        canvas.height = height * devicePixelRatio;
        context.scale(devicePixelRatio, devicePixelRatio);
        const gradient = context.createLinearGradient(0, 0, 0, height);
        gradient.addColorStop(0, '#818cf8');
        gradient.addColorStop(1, '#4338ca');
        context.fillStyle = gradient;
        context.beginPath();
        context.roundRect(20, 40, 60, height - 60, [8, 8, 0, 0]);
        context.fill();
        context.font = '14px sans-serif';
        context.fillText('Sales', 20, 24);
      }).observe(canvas);
    });
  }
}
```

The whole [CanvasRenderingContext2D](https://developer.mozilla.org/en-US/docs/Web/API/CanvasRenderingContext2D) is there: paths, `Path2D` (with SVG path data), rectangles, arcs and rounded rectangles, transforms, clipping, line widths, joins and dashes, colors, linear, radial and conic gradients, patterns, shadows, `globalAlpha` and every `globalCompositeOperation`, text with `font`, `textAlign`, `textBaseline`, `direction`, `letterSpacing` and `measureText()`, `drawImage()` of images, `ImageBitmap`s and other canvases, and `getImageData()`, `putImageData()` and `isPointInPath()`.

Canvases the page doesn't show work too: `document.createElement('canvas')` and `new OffscreenCanvas(width, height)` have a 2D context, and can be drawn on another canvas, made a pattern, uploaded as a WebGL texture (three.js's `CanvasTexture`) or saved as an image. That's how three.js apps draw text labels, and how image libraries resize a photo.

## Drawing in 3D

Give the canvas a size with CSS, and draw once it's laid out:

```typescript title="src/app/scene.ts"
import {
  afterNextRender,
  Component,
  type ElementRef,
  viewChild,
} from '@angular/core';
import { LYNX_ELEMENTS, type LynxCanvasElement } from '@blotch/angular-lynx';
import * as THREE from 'three';

@Component({
  selector: 'app-scene',
  imports: [LYNX_ELEMENTS],
  template: `<canvas #canvas class="h-[300px] w-full"></canvas>`,
})
export class Scene {
  readonly canvas = viewChild.required<ElementRef<LynxCanvasElement>>('canvas');

  constructor() {
    afterNextRender(() => {
      const canvas = this.canvas()
        .nativeElement as unknown as HTMLCanvasElement;
      const renderer = new THREE.WebGLRenderer({ canvas, antialias: true });
      renderer.setPixelRatio(devicePixelRatio);
      const scene = new THREE.Scene();
      const camera = new THREE.PerspectiveCamera(50, 1, 0.1, 100);
      camera.position.z = 3;
      const cube = new THREE.Mesh(
        new THREE.BoxGeometry(),
        new THREE.MeshNormalMaterial(),
      );
      scene.add(cube);

      // Fit the drawing buffer to the canvas's size.
      new ResizeObserver(([entry]) => {
        const { width, height } = entry.contentRect;
        renderer.setSize(width, height, false);
        camera.aspect = width / height;
        camera.updateProjectionMatrix();
      }).observe(canvas);

      renderer.setAnimationLoop(() => {
        cube.rotation.y += 0.01;
        renderer.render(scene, camera);
      });
    });
  }
}
```

Like an HTML canvas:

- `width` and `height` are the drawing buffer's size in pixels, 300 by 150 to start. The element's CSS size is how big it's shown.
- `getContext('2d')` and `getContext('webgl2')` return the same context every time. A canvas has the kind of context it was first asked for: after `getContext('2d')`, `getContext('webgl2')` is `null`, and the other way round. `'webgl'` (WebGL 1) is `null`: three.js needs WebGL2 anyway.
- The build includes the WebGL2 context only when a module of your app or its libraries names `'webgl2'`, as three.js and `getContext('webgl2')` do, so an app that never draws in 3D doesn't load its code (about 37 kB of the main-thread script). So on iOS and Android, a context name built at runtime gets `null` and a console warning, unless another module named `'webgl2'`: write the name out, or call `ɵenableWebGL2()` from `@blotch/angular-lynx` before `getContext()`. The web preview's canvas is the browser's, which has its own context.
- Pointer events (`pointerdown`, `pointermove`, `pointerup` and the rest) work, from the finger's touches. They work on every element, not only a canvas: see [Element events](/api/angular-lynx/element-events).
- `clientWidth`, `clientHeight` and `getBoundingClientRect()` answer from the element's last layout, and `ResizeObserver` reports its size as it changes.

## angular-three

[angular-three](https://github.com/angular-threejs/angular-three) works with its own renderer, as on the web:

```typescript title="src/app/app.config.ts"
import { provideZonelessChangeDetection } from '@angular/core';
import { provideRenderer } from '@blotch/angular-lynx';
import { provideNgtRenderer } from 'angular-three/dom';

export const appConfig = {
  providers: [
    provideZonelessChangeDetection(),
    provideRenderer(),
    provideNgtRenderer(),
  ],
};
```

`provideRenderer()` comes first: angular-three's renderer wraps Angular's, which on Lynx is AngularLynx's. `<ngt-canvas>` sizes itself, and its events (`(click)`, `(pointerover)` on a mesh) come from touches.

:::warning
angular-three 4.2 lists Angular 20 and 21, and three.js below 0.183, as its peer dependencies. On Angular 22, install it with `npm install angular-three --legacy-peer-deps`, or add an [`overrides`](https://docs.npmjs.com/cli/configuring-npm/package-json#overrides) entry. Pin `three` to `0.182.x`.
:::

## Images and models

Textures and models load as on the web:

- three.js's `TextureLoader` (an `Image`), `ImageBitmapLoader` (`createImageBitmap()`) and `GLTFLoader`, including `.glb` files with their textures inside.
- From `https://` URLs, `data:` URLs, object URLs (`URL.createObjectURL()`), and files your app bundles, by their path in `dist/`: copy a model in with [`output.copy`](https://rsbuild.rs/config/output/copy) in `lynx.config.ts`, then load `'/assets/models/frame.glb'`. A build has no loader for `import model from './frame.glb'`.

The phone decodes images, and the pixels go straight to the GPU. A canvas, drawn in 2D or with WebGL, uploads as a texture too (`CanvasTexture`, or `texImage2D()` with the canvas): the phone reads its pixels and hands them to the GPU. Loaders that need Web Workers or WebAssembly, such as `DRACOLoader` and `KTX2Loader`, don't work.

`createImageBitmap()` takes the same sources as on the web, and makes a bitmap of a part of one with the crop arguments:

```typescript
// The second 32 by 32 sprite of a sprite sheet.
const sprite = await createImageBitmap(sheet, 32, 0, 32, 32);
```

- **Any source can be cropped:** a `Blob`, a loaded `Image`, a canvas (a `<canvas>`, `document.createElement('canvas')` or an `OffscreenCanvas`), an `ImageBitmap` or an `ImageData`. The part of the rectangle outside the source is transparent.
- **An `ImageBitmap` is copied** with the options you pass: flipped, premultiplied or resized.
- **The phone copies the pixels.** A canvas, a bitmap or an `Image` is copied from the pixels the phone already has, so nothing crosses to JavaScript and no file is decoded again. An `ImageData`'s pixels go to the phone once.
- **`OffscreenCanvas.transferToImageBitmap()`** hands over its image and clears the canvas, as on the web.
- **An ejected app keeps its older shell**, which rejects an `ImageBitmap`, an `ImageData`, a loaded `Image` and a crop. To take them in without losing your own native changes, merge the new `App/AngularLynxWebGL.m` (iOS) or `WebGLModule.kt` (Android) from `node_modules/@blotch/angular-lynx-native/templates` into your copy.
- **Make a WebGL canvas's bitmap in the function that draws**, as with `toBlob()` below. Once the frame is on screen, its drawing buffer is cleared, unless you asked for `preserveDrawingBuffer: true`.

## Videos

A [`<video>`](/api/elements/video) is an image too. Draw its frame for a thumbnail or a filter, or play it on a three.js mesh with **`VideoTexture`**:

```typescript title="src/app/thumbnail.ts"
import { Component, type ElementRef, viewChild } from '@angular/core';
import { LYNX_ELEMENTS, type LynxCanvasElement } from '@blotch/angular-lynx';

@Component({
  selector: 'app-thumbnail',
  imports: [LYNX_ELEMENTS],
  template: `
    <video
      #video
      src="https://example.com/clip.mp4"
      class="h-[180px] w-full"
      (bindfirstframe)="grab()"
    ></video>
    <canvas #thumb width="160" height="90" class="h-[90px] w-[160px]"></canvas>
  `,
})
export class Thumbnail {
  readonly video = viewChild.required<ElementRef<HTMLVideoElement>>('video');
  readonly thumb = viewChild.required<ElementRef<LynxCanvasElement>>('thumb');

  grab(tries = 10): void {
    const video = this.video().nativeElement;
    // Draw only once there's a frame: try again a little later until then.
    if (video.readyState < video.HAVE_CURRENT_DATA) {
      if (tries > 0) setTimeout(() => this.grab(tries - 1), 100);
      return;
    }
    const canvas = this.thumb().nativeElement as unknown as HTMLCanvasElement;
    canvas.getContext('2d')!.drawImage(video, 0, 0, 160, 90);
  }
}
```

For a mesh, pass the same element to three.js: `new THREE.VideoTexture(video)`. It waits for the frame by itself.

- The phone reads the frame the video shows; the pixels never pass through JavaScript. `createImageBitmap(video)` keeps a copy of it, as on the web.
- Before its first frame, `videoWidth` is 0, `readyState` is `HAVE_NOTHING`, and nothing is drawn, as in a browser.
- Check `readyState` before you draw, and try again if there's no frame yet, as above. On the phone the frame is usually there when `bindfirstframe` arrives, but iOS waits for it for half a second at most, then sends the event anyway. The web preview never sends `bindfirstframe`: draw from a tap or a `bindtimeupdate` there.
- A video whose file says to turn it (a phone recording in portrait) is drawn turned, as it plays, and `videoWidth` and `videoHeight` are its turned size, as in a browser.
- The web preview doesn't take a template's `<video>` in `drawImage()`, `texImage2D()` or `createImageBitmap()` yet ([#732](https://github.com/Blotch-Smart-Frames/AngularLynx/issues/732)).

## Save it as an image

`toBlob()` and `toDataURL()` work as on an HTML canvas: they encode what the canvas shows as a PNG, or a JPEG for `'image/jpeg'`, with a quality from 0 to 1 (0.92 when you don't give one). Any other type gives a PNG, as in browsers.

```typescript
canvas.toBlob(
  (blob) => {
    if (blob) this.photo.set(URL.createObjectURL(blob));
  },
  'image/jpeg',
  0.9,
);
```

The `Blob` is ready to show in an `<image>`, upload, or [share](/guide/share). The phone encodes the image, so it's quick: a 2048 by 1365 JPEG takes about 20 ms on the iOS Simulator and 35 ms on the Android emulator, plus 15 ms before the callback has the `Blob`. A PNG of that size is slower to encode, around 100 ms on the iOS Simulator and 300 ms on the Android emulator, and is several times larger.

- **With WebGL, call it right after you draw.** A 2D canvas keeps what's drawn on it, but WebGL clears the drawing buffer once a frame is on screen, as in a browser. So call `toBlob()` in the same function that draws, such as right after three.js's `renderer.render()`, or make the context with `preserveDrawingBuffer: true` (three.js: `new WebGLRenderer({ preserveDrawingBuffer: true })`). Called later without it, you get a transparent image.
- **The callback runs later,** as on the web: `toBlob()` reads the canvas when you call it, and the callback gets the `Blob` once it's ready. `toDataURL()` returns at once.
- **A JPEG has no transparency:** transparent pixels come out black, as in browsers. A PNG keeps them.
- **A canvas without a context encodes as a transparent image** of its size, as in browsers. **Nothing to encode gives `null`** (`toBlob()`) or `'data:,'` (`toDataURL()`): a canvas with no width or height, one whose context was lost, or Lynx Explorer, which has no canvas.
- **Prefer `toBlob()`.** A `data:` URL holds the image as text a third larger than the file, and building it is all at once.

## Performance

Your scene's JavaScript runs on the thread Lynx lays the page out on, and each frame's WebGL calls go to the phone's GPU together, once a frame. A scene of a few meshes, lit and shadowed, draws at 60 frames a second in the iOS Simulator and on the Android emulator. Keep the drawing buffer to the screen's pixel ratio, at most 2, and stop the loop (`setAnimationLoop(null)`) when the scene is off screen. The first time an app runs after it's installed, each material's shaders compile when it's first drawn (up to 2 seconds for the first one in the iOS Simulator); later launches reuse them.

:::tip
The iOS Simulator and the Android emulator both draw on the Mac's GPU, so a scene that's smooth there is a fair guide, but check frame rates on a phone before you ship: a phone's GPU is slower than a Mac's.
:::

## What's different from the web

- The 2D context's `filter` takes the CSS filter functions (`blur()`, `drop-shadow()`, `grayscale()` and the other color functions), but a `url()` filter is kept and not applied, as Lynx has no SVG filters. A filter works on the pixels of a layer the canvas's size, on the main thread, so each shape drawn with one costs about as much as a canvas-sized image: draw what shares a filter into a canvas of its own and filter that once with `drawImage()`, rather than filtering many small shapes.
- `wordSpacing`, `fontKerning`, `fontStretch`, `fontVariantCaps` and `textRendering` are kept but don't change the text. Text drawn with a gradient, a pattern or `strokeText()` is drawn from the glyphs' outlines, so color emoji show only with a plain `fillStyle`.
- A `<video>` draws its current frame, on a 2D canvas or as a texture, only once it has one (`readyState` at least `HAVE_CURRENT_DATA`), whether it's shown or hidden with `display: none`.
- `getContext('bitmaprenderer')` is `null`: draw an `ImageBitmap` with a 2D context's `drawImage()` instead.
- `toBlob()` and `toDataURL()` make the main thread wait while the phone reads and encodes the canvas (tens of milliseconds for a photo), where a browser's `toBlob()` encodes in the background.
- A lost context isn't restored: make a new renderer.
- `crypto.randomUUID()`, which AngularLynx adds for angular-three, isn't cryptographically secure: don't use it for secrets.
