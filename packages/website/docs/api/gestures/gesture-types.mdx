# Gesture types

The six gesture classes, their options, the callbacks each supports and the event each passes. `import { PanGesture, TapGesture } from '@blotch/angular-lynx';`

## Usage

```typescript
readonly pan = new PanGesture()
  .minDistance(10) // options
  .onUpdate((event) => this.offset.set(event.translationX)); // callbacks
```

Create a gesture with `new`, chain its options and callbacks, then bind it with [`[lynxGesture]`](/api/gestures/). Every option and callback returns the gesture.

## Common to every gesture

| Option           | Type      | Default | Description                                                                                             |
| ---------------- | --------- | ------- | ------------------------------------------------------------------------------------------------------- |
| `enabled(value)` | `boolean` | `true`  | Meant to turn the gesture off and on, but does nothing yet (see [below](#options-lynx-doesnt-read-yet)) |

| Callback        | Tap, LongPress | Pan, Fling, Pinch, Rotation |
| --------------- | -------------- | --------------------------- |
| `onBegin`       | Yes            | Yes                         |
| `onStart`       | Yes            | Yes                         |
| `onUpdate`      | No             | Yes                         |
| `onEnd`         | Yes            | Yes                         |
| `onTouchesDown` | Yes            | Yes                         |
| `onTouchesUp`   | Yes            | Yes                         |

When each one fires is on [Lifecycle](/api/gestures/lifecycle#callbacks). A `—` default below means AngularLynx doesn't send the option, so Lynx uses its own default.

You never need an empty `onBegin`. Lynx's fling handler, and its pan handler before Lynx 3.9, skip `onStart` and `onEnd` unless an `onBegin` is registered, so AngularLynx registers one on every pan, fling, pinch and rotation that has none.

### Positions: `x` and `absoluteX`

- **`x`, `y`**: the finger's position from the top-left corner of the element that has the gesture.
- **`absoluteX`, `absoluteY`**: the finger's position from the top-left corner of the [`page`](/guide/glossary#page), the root of your app.
- **`translationX`, `translationY`** (pan only): how far the finger has moved since it touched down. AngularLynx works it out from `absoluteX` and `absoluteY`, because Lynx reports only positions.

## TapGesture

Recognizes a quick touch and release.

```typescript
readonly tap = new TapGesture().maxDistance(20).onEnd((event) => this.select(event.x));
```

| Option            | Type     | Default | Description                                                |
| ----------------- | -------- | ------- | ---------------------------------------------------------- |
| `maxDuration(ms)` | `number` | `500`   | The longest the finger can stay down. A longer touch fails |
| `maxDistance(px)` | `number` | `10`    | How far the finger can move. Moving further fails the tap  |
| `numberOfTaps(n)` | `number` | —       | Does nothing on a device yet (see below)                   |

**Callbacks:** `onBegin`, `onStart`, `onEnd`, `onTouchesDown`, `onTouchesUp`. `onEnd` fires only when the tap succeeded.

```typescript
interface TapGestureEvent extends GestureEvent {
  x: number;
  y: number;
}
```

:::info Double taps
No Lynx platform counts taps, so `numberOfTaps(2)` still fires on the first tap. To detect a double tap, compare the times of successive `onEnd` calls yourself.
:::

## PanGesture

Tracks a finger dragging across the element. `onUpdate` fires on every move.

```typescript
readonly pan = new PanGesture()
  .minDistance(10)
  .onUpdate((event) => this.offset.set(event.translationX))
  .onEnd(() => this.settle());
```

A **pointer** is one finger touching the screen. `minPointers(2)` means the gesture needs two fingers.

| Option                  | Type                         | Default | Description                                                                   |
| ----------------------- | ---------------------------- | ------- | ----------------------------------------------------------------------------- |
| `minDistance(px)`       | `number`                     | `0`     | How far the finger moves before the pan activates. `0` activates at once      |
| `activeOffsetX(offset)` | `number \| [number, number]` | —       | Activate after this much horizontal movement. A number means either direction |
| `activeOffsetY(offset)` | `number \| [number, number]` | —       | The same, vertically                                                          |
| `failOffsetX(offset)`   | `number \| [number, number]` | —       | Fail after this much horizontal movement before activating                    |
| `failOffsetY(offset)`   | `number \| [number, number]` | —       | Fail after this much vertical movement. Lets a vertical scroll take over      |
| `minPointers(n)`        | `number`                     | —       | The fewest fingers the pan needs                                              |
| `maxPointers(n)`        | `number`                     | —       | The most fingers the pan allows                                               |

Lynx reads only `minDistance` so far. The other options do nothing yet: see [Options Lynx doesn't read yet](#options-lynx-doesnt-read-yet).

**Callbacks:** all six.

```typescript
interface PanGestureEvent extends GestureEvent {
  translationX: number;
  translationY: number;
  velocityX: number;
  velocityY: number;
}
```

`translationX` is measured from where the finger touched down, when `onBegin` fires. So at `onStart` it already includes the distance the finger moved before the pan activated, such as the 10 pixels of `minDistance(10)`. Lynx doesn't report velocity yet, so `velocityX` and `velocityY` are `undefined`.

## FlingGesture

Follows the momentum of a quick drag after the finger lifts, the way a list keeps scrolling after a flick.

```typescript
import { FlingGesture, Gesture, PanGesture } from '@blotch/angular-lynx';

readonly drag = new PanGesture().onUpdate((event) => this.follow(event));
readonly fling = new FlingGesture()
  .onUpdate((event) => this.coast(event.params?.['deltaX'] as number))
  .onEnd(() => this.settle());

// Bind this one with [lynxGesture]="gesture".
readonly gesture = Gesture.Simultaneous(this.drag, this.fling);
```

**Give the element a pan as well**, with `Gesture.Simultaneous`. Lynx flings only the element that won the touch, and a fling ignores the touch until the finger lifts, so on its own it rarely fires.

| Option                | Type             | Default | Description                                         |
| --------------------- | ---------------- | ------- | --------------------------------------------------- |
| `direction(dir)`      | `FlingDirection` | —       | The directions to recognize. Combine them with `\|` |
| `numberOfPointers(n)` | `number`         | —       | The exact number of fingers the fling needs         |

Lynx doesn't read either option yet: every fling fires, in any direction.

**Callbacks:**

- `onBegin` fires when the finger lifts.
- `onUpdate` fires on every frame of the fling. The event's `deltaX` and `deltaY` say how far it moved since the last frame.
- `onEnd` fires when the fling stops, or as soon as the finger lifts if it was too slow to fling.
- `onStart` doesn't fire: Lynx starts a fling that follows a touch without activating it.

```typescript
interface FlingGestureEvent extends GestureEvent {
  velocityX: number; // undefined: Lynx doesn't report velocity yet
  velocityY: number;
}
```

The event also has Lynx's `deltaX` and `deltaY`, which the type doesn't declare yet. Read them from `event.params`.

## LongPressGesture

Recognizes a finger held still on the element.

```typescript
readonly hold = new LongPressGesture().minDuration(800).onStart(() => this.openMenu());
```

| Option            | Type     | Default | Description                                                     |
| ----------------- | -------- | ------- | --------------------------------------------------------------- |
| `minDuration(ms)` | `number` | `500`   | How long the finger must stay down before the gesture activates |
| `maxDistance(px)` | `number` | `10`    | How far the finger can drift. Drifting further fails it         |

**Callbacks:** `onBegin`, `onStart`, `onEnd`, `onTouchesDown`, `onTouchesUp`. `onStart` fires once the hold is long enough. `onEnd` fires when the finger lifts after a successful long press.

```typescript
interface LongPressGestureEvent extends GestureEvent {
  x: number;
  y: number;
  duration: number;
}
```

## PinchGesture and RotationGesture

Two-finger zoom and rotate. Neither class has options.

:::warning These don't fire yet
No Lynx platform has a native pinch or rotation handler, so these gestures never fire on a device. You can still compose them, for example `Gesture.Simultaneous(pan, pinch)`, but drive zoom from a pan or on-screen buttons for now.
:::

**Callbacks:** all six.

```typescript
interface PinchGestureEvent extends GestureEvent {
  scale: number; // 1 means unchanged
  velocity: number;
}

interface RotationGestureEvent extends GestureEvent {
  rotation: number;
  velocity: number;
}
```

## Why the defaults are sent

Once a gesture sends any option, Lynx reads every option it leaves out as `0`. Without the defaults, a tap that set only `numberOfTaps` would get a `maxDuration` of 0 and fail the instant a finger lands. So `TapGesture`, `LongPressGesture` and `PanGesture` always send their full default set, shown above, and every other gesture sends `{ enabled: true }`. You don't need to set them yourself.

## Options Lynx doesn't read yet

Lynx 4.1's native handlers read only these options:

- `TapGesture`: `maxDuration`, `maxDistance`
- `LongPressGesture`: `minDuration`, `maxDistance`
- `PanGesture`: `minDistance`

AngularLynx sends the others, but they don't change anything on a device yet:

- **`enabled(false)`** doesn't turn a gesture off. To turn one off, bind `[lynxGesture]` to a list without it, such as `[lynxGesture]="draggable() ? pan : []"`.
- **A pan's `activeOffsetX`, `activeOffsetY`, `failOffsetX`, `failOffsetY`, `minPointers` and `maxPointers`.** To let a scroll view take a mostly vertical drag, call `fail()` from `onUpdate` instead (see [Lifecycle](/api/gestures/lifecycle)).
- **A fling's `direction` and `numberOfPointers`.** Check `deltaX` and `deltaY` in `onUpdate` instead.
- **A tap's `numberOfTaps`** (see [Double taps](#tapgesture)).

## If no gesture fires

Lynx ignores every gesture, with no error, unless the bundle was built with `enableNewGesture: true`. AngularLynx turns it on by default. If you pass [plugin options](/api/build/#plugin-options) in `lynx.config.ts`, don't set it to `false`.

## Types

```typescript
interface GestureEvent {
  state?: GestureState; // usually absent: the callback tells you the phase
  absoluteX?: number;
  absoluteY?: number;
  params?: Record<string, unknown>; // Lynx's raw event fields
}

enum FlingDirection {
  RIGHT = 1,
  LEFT = 2,
  UP = 4,
  DOWN = 8,
}

enum GestureType {
  PAN = 0,
  FLING = 1,
  DEFAULT = 2,
  TAP = 3,
  LONGPRESS = 4,
  ROTATION = 5,
  PINCH = 6,
  NATIVE = 7,
}
```

Every event also has Lynx's raw fields as properties, such as `pageX` and `clientX`. `params` holds the same fields. `GestureState` is on [Lifecycle](/api/gestures/lifecycle#types).
