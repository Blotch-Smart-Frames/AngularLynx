# Event reference

Every event [`fireEvent`](/api/testing-library/#fireeventelement-event) has a method for, and the template binding each one runs.

```typescript
fireEvent.tap(element); // runs (bindtap) or (catchtap), then the ancestors'
fireEvent.input(element, { detail: { value: 'hello' } }); // $event.detail.value
```

Each method takes the element and an optional `init` object. It runs the element's `(bind*)` or `(catch*)` handler. Touch, mouse and key events then go up to the page, as on a device, until a `(catch*)` handler stops them. The other events stay on the element.

| Method                  | Binding             |
| ----------------------- | ------------------- |
| `fireEvent.tap`         | `(bindtap)`         |
| `fireEvent.longpress`   | `(bindlongpress)`   |
| `fireEvent.longtap`     | `(bindlongtap)`     |
| `fireEvent.touchstart`  | `(bindtouchstart)`  |
| `fireEvent.touchmove`   | `(bindtouchmove)`   |
| `fireEvent.touchend`    | `(bindtouchend)`    |
| `fireEvent.touchcancel` | `(bindtouchcancel)` |

## Coming into view

| Method                  | Binding             |
| ----------------------- | ------------------- |
| `fireEvent.uiappear`    | `(binduiappear)`    |
| `fireEvent.uidisappear` | `(binduidisappear)` |

A device sends `uiappear` when an element comes into view, and `uidisappear` when it leaves. The [`lynxExposure` directive](/guide/exposure) and `IntersectionObserver` listen for them, so firing one is how a test scrolls an element into view:

```typescript
fireEvent.uiappear(frame);
await waitForUpdate();
```

## Layout and loading

| Method                   | Binding              |
| ------------------------ | -------------------- |
| `fireEvent.layoutchange` | `(bindlayoutchange)` |
| `fireEvent.load`         | `(bindload)`         |
| `fireEvent.error`        | `(binderror)`        |
| `fireEvent.bgload`       | `(bindbgload)`       |
| `fireEvent.bgerror`      | `(bindbgerror)`      |

An `<image>`, `<svg>`, `<frame>` or `<webview>` fires `load` once its content arrives, and an `<image>`, `<video>`, `<webview>` or `<overlay>` fires `error` when it fails. Pass what the element would report as `detail`, such as an image's size:

```typescript
fireEvent.load(image, { detail: { width: 240, height: 340 } });
await waitForUpdate();
```

## Other events

For an event without a method, create it yourself. Its type is the binding's event type and the event name, joined by a colon:

```typescript
fireEvent(element, new Event('bindEvent:change')); // runs (bindchange)
```

A `CustomEvent`'s `detail` reaches the handler as `$event.detail`. A `<viewpager>` that moved to its third page:

```typescript
fireEvent(
  pager,
  new CustomEvent('bindEvent:change', {
    detail: { index: 2, isDragged: true },
  }),
);
```
