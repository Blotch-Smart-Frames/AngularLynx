# @blotch/angular-lynx-testing-library

Renders a component through the Lynx renderer in a unit test, then finds and taps its elements with Testing Library queries that read Lynx's accessibility attributes. `import { render } from '@blotch/angular-lynx-testing-library';`

## Usage

```typescript title="src/app/counter/counter.ts"
import { Component, signal } from '@angular/core';
import { LYNX_ELEMENTS } from '@blotch/angular-lynx';

@Component({
  selector: 'app-counter',
  imports: [LYNX_ELEMENTS],
  template: `
    <view
      [accessibility-element]="true"
      accessibility-traits="button"
      accessibility-label="Add one"
      (bindtap)="increment()"
    >
      <text>Taps: {{ taps() }}</text>
    </view>
  `,
})
export class Counter {
  readonly taps = signal(0);

  increment(): void {
    this.taps.update((n) => n + 1);
  }
}
```

```typescript title="src/app/counter/counter.test.ts"
import {
  fireEvent,
  render,
  waitForUpdate,
} from '@blotch/angular-lynx-testing-library';
import { describe, expect, it } from 'vitest';

import { Counter } from './counter';

describe('Counter', () => {
  it('counts taps', async () => {
    const { getByRole, getByText } = await render(Counter);

    fireEvent.tap(getByRole('button', { name: 'Add one' }));
    await waitForUpdate();

    expect(getByText('Taps: 1')).toBeTruthy();
  });
});
```

Add the library with [`ng generate @blotch/angular-lynx:add-testing`](/api/schematics#add-testing), and run tests with `ng test`. The [unit-test builder](/api/build/#unit-test) loads the library's setup, so there's no setup file to write.

## API

### `render(component, options?)`

```typescript
function render<Q extends Queries = typeof queries>(
  component: Type<unknown>,
  options?: RenderOptions<Q>,
): Promise<RenderResult<Q>>;
```

Bootstraps `component` as a Lynx app, renders it into the test's DOM, and resolves once the first render is done.

- It first destroys the app a previous `render()` left, and clears `document.body`.
- The app gets `provideZonelessChangeDetection()`, `provideRenderer()` and your `options.providers`.
- Elements render under a `<page>` element, the result's `container`.

### `cleanup()`

```typescript
function cleanup(): void;
```

Destroys the rendered app. It runs after every test, so you rarely call it. To turn that off, set the environment variable `ATL_SKIP_AUTO_CLEANUP=true`.

### `waitForUpdate()`

```typescript
function waitForUpdate(): Promise<void>;
```

Waits one task (a `setTimeout` of 0), so the change detection Angular scheduled can run, then runs change detection once more. Await it after `fireEvent` or after setting a signal, before you check the rendered output.

### `fireEvent(element, event)`

```typescript
fireEvent(element: Element, event: Event): boolean;
fireEvent.tap(element: Element, init?: Record<string, unknown>): boolean;
// … one method per event in the Event reference
```

Fires a Lynx event at `element`, which runs the handlers a device would, such as `(bindtap)`. The methods and their bindings are in the [Event reference](/api/testing-library/event-reference).

- **Bubbling**: touch, mouse and key events go from `element` up to the page, as on a device, so a tap on a row reaches its card's `(click)`. A `(catch*)` handler runs and stops the event there, and `(capture-*)` handlers run first, from the page down. Other events, such as `scroll` and `input`, run only `element`'s own handler.
- **`init`**: properties to set on the event. `{ detail: { value: 'hi' } }` arrives as `$event.detail.value`.
- **`init.bubbles`**: overrides whether the event goes up to the page. `{ bubbles: false }` keeps a tap on `element`.
- **`init.eventType`**: fires at one kind of handler on `element` alone, such as `'catchEvent'` for its `(catch*)` handler.

**`fireEvent` doesn't render.** The handler runs before `fireEvent` returns, so a spy or a signal you read directly already shows the change. Angular renders the result in a change detection it schedules for after the current task. Await `waitForUpdate()` before checking the rendered output.

### `eventMap`

```typescript
const eventMap: Record<string, { defaultInit: { bubbles?: boolean } }>;
```

The events that `fireEvent` has a method for, keyed by event name. `defaultInit.bubbles` is `true` for the events that go up to the page.

### `*ByAccessibilityLabel`

```typescript
getByAccessibilityLabel(label: Matcher, options?: MatcherOptions): HTMLElement;
// getAllBy…, queryBy…, queryAllBy…, findBy… and findAllBy… too
```

Finds elements by their `accessibility-label`, the text a screen reader reads for them. Testing Library's `*ByLabelText` reads `<label>` and `aria-*` attributes, which Lynx elements don't have.

- **`label`**: a string, a RegExp or a function, as for `getByText`.
- **`options`**: `exact: false` matches part of the label in any case. `normalizer` changes how whitespace is trimmed.
- **Variants**: the same six as Testing Library's queries. `findBy…` waits for the element, 1 second by default.

### `*ByRole`

```typescript
getByRole(role: ByRoleMatcher, options?: ByRoleOptions): HTMLElement;
// getAllBy…, queryBy…, queryAllBy…, findBy… and findAllBy… too
```

Testing Library's `*ByRole`, reading Lynx's accessibility attributes as a screen reader does. It finds what Testing Library finds too, such as an `<input>` as a `textbox`.

| `accessibility-traits` | Role        |
| ---------------------- | ----------- |
| `button`               | `button`    |
| `link`                 | `link`      |
| `image`                | `img`       |
| `header`               | `heading`   |
| `search`               | `searchbox` |
| `adjustable`           | `slider`    |
| `tabbar`               | `tablist`   |

- **`<image>` is an `img`** unless it sets `accessibility-traits`. Other traits, such as `text`, give no role.
- **Only reachable elements match.** A screen reader reaches `<text>`, `<image>`, and other elements with `accessibility-element="true"`, outside `accessibility-elements-hidden`. A `tabbar` is read from the container around the tabs, so it needs no `accessibility-element`. Pass `hidden: true` to include the rest.
- **`name`** is the `accessibility-label`. A `<text>` without one is named by its text. A `<view>` isn't named by the text inside it, since iOS doesn't read it.
- **`selected`** is the `selected` trait: `accessibility-traits="button,selected"`, which an active `routerLinkActive` element gets. iOS reads a comma-separated list, but Android reads only one trait.
- **`value: { text }`** is the `accessibility-value`.
- **Other ARIA states**, such as `checked` or `expanded`, have no Lynx attribute, so a Lynx element never has them.

### `screen`

Every query, bound to `document.body`, with Testing Library's `debug()` and `logTestingPlaygroundURL()`.

### `within(element, queries?)`

```typescript
function within(element: HTMLElement): BoundLynxQueries;
function within<Q extends Queries>(
  element: HTMLElement,
  queries: Q,
): BoundFunctions<Q>;
```

Binds every query to `element`, to search one part of the tree. Pass `queries` to bind only those. `getQueriesForElement` is the same function.

### `queries`

```typescript
const queries: LynxQueries;
```

Every query, unbound, each taking the container first: Testing Library's, with `*ByRole` and `*ByAccessibilityLabel` from this library. Each one is also exported on its own, such as `getByAccessibilityLabel(container, 'Close')`.

## Types

### `RenderOptions`

```typescript
type RenderOptions<Q extends Queries = typeof queries> = {
  providers?: (Provider | EnvironmentProviders)[];
  queries?: Q;
};
```

| Property    | Description                                                                        |
| ----------- | ---------------------------------------------------------------------------------- |
| `providers` | Extra providers for the test app, such as `provideRouter(routes)`                  |
| `queries`   | Custom queries to bind to `container`, next to the library's [`queries`](#queries) |

### `RenderResult`

| Property       | Type                                             | Description                                                                       |
| -------------- | ------------------------------------------------ | --------------------------------------------------------------------------------- |
| `container`    | `Element`                                        | The `<page>` element that holds everything rendered                               |
| `componentRef` | `ComponentRef<unknown>`                          | The root component. Use `componentRef.injector.get(Token)` to reach a service     |
| `unmount`      | `() => void`                                     | Destroys the app, like `cleanup()`                                                |
| `rerender`     | `(component, options?) => Promise<RenderResult>` | Renders another component in its place                                            |
| `asFragment`   | `() => DocumentFragment`                         | A copy of `container`, for snapshot tests                                         |
| `getByText`, … | Query functions                                  | Every query in [`queries`](#queries), bound to `container`, plus your custom ones |

`componentRef.setInput()` works under `ng test`, which compiles components ahead of time. Under plain Vitest, which compiles them at runtime, it can't see signal inputs. Set a writable signal on `componentRef.instance` instead.

### Query types

| Type                             | Description                                                  |
| -------------------------------- | ------------------------------------------------------------ |
| `LynxQueries`                    | The type of [`queries`](#queries)                            |
| `BoundLynxQueries`               | Every query bound to a container, as `within()` returns them |
| `BoundAccessibilityLabelQueries` | The `*ByAccessibilityLabel` queries bound to a container     |
| `LynxScreen`                     | The type of [`screen`](#screen)                              |

## Re-exports

| Export         | From                   | Description                |
| -------------- | ---------------------- | -------------------------- |
| `ComponentRef` | `@angular/core` (type) | The type of `componentRef` |
