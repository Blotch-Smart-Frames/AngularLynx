# CLI

The `@blotch/dolan` CLI copies UI components into your app, then tells you when they change and merges the updates for you. Run every command from your project folder.

```bash
npx @blotch/dolan <command> [options]
```

- Once `@blotch/dolan` is a dependency (see [installation](/dolan/#installation)), `npx` runs your installed copy. The shorter `npx dolan <command>` works too.
- `npx @blotch/dolan --help` lists the commands, and `<command> --help` lists a command's options. `--version` prints the version.
- Every command except `info` needs a `dolan.config.json`. Run [`init`](#init) first.
- In CI, a script or an AI agent, the commands ask nothing. See [Without a terminal](#without-a-terminal).

| Command                 | What it does                                            |
| ----------------------- | ------------------------------------------------------- |
| [`init`](#init)         | Set up dolan and copy the theme files                   |
| [`add`](#add)           | Copy components into your app                           |
| [`list`](#list)         | Show installed components and their status              |
| [`info`](#info)         | Show a component's files and dependencies               |
| [`diff`](#diff)         | Show how your copy differs from the bundled source      |
| [`outdated`](#outdated) | List components that aren't up to date (exits 1 if any) |
| [`update`](#update)     | Merge the bundled source into your copies               |
| [`remove`](#remove)     | Delete a component                                      |
| [`eject`](#eject)       | Stop recording a component's file hashes                |
| [`theme`](#theme)       | List theme files, or start a new one                    |
| [`doctor`](#doctor)     | Check your setup                                        |

## Where updates come from

The CLI package contains the component source. It doesn't download anything. So "upstream" in every command means the source bundled with the `@blotch/dolan` version you have installed.

To get newer components, upgrade the CLI and then update:

```bash
npm install @blotch/dolan@latest
npx @blotch/dolan update
```

The CLI keeps two files at the project root. Commit both.

- **`dolan.config.json`:** where components and theme files go. Paths are relative to the project folder.
- **`dolan.lock.json`:** a hash of every copied file, as it was when dolan wrote it. Comparing it with your file and the bundled source tells dolan who changed what.

```json title="dolan.config.json"
{
  "aliases": {
    "components": "src/components/ui",
    "theme": "src/styles"
  }
}
```

If your project has an `.oxfmtrc.json` and oxfmt installed, dolan formats the `.ts` files it writes with your settings.

## Without a terminal

In CI, a script or an AI agent, a command's input isn't a terminal, so nobody can answer its questions. The commands then ask nothing, and each question takes its default answer. Where a question has no default, or its default would cancel the run, the command exits with code 1 before changing anything, and says what to pass instead.

| Command             | Question                                    | Without a terminal                                                                 |
| ------------------- | ------------------------------------------- | ---------------------------------------------------------------------------------- |
| [`init`](#init)     | Where should components and theme files go? | Uses `--components` and `--theme`, or the defaults.                                |
|                     | Overwrite `dolan.config.json`?              | Exits 1. Add `--force` to overwrite it.                                            |
|                     | Overwrite theme files that differ?          | Keeps yours.                                                                       |
| [`add`](#add)       | Which components? (no names given)          | Exits 1. Name them: `add button card`.                                             |
|                     | Overwrite installed components?             | Skips them. Add `--force` to overwrite them.                                       |
| [`update`](#update) | Apply the auto-updates?                     | Applies them.                                                                      |
|                     | How should each conflict be resolved?       | Applies the rest, leaves the conflicts alone and exits 1. See [`update`](#update). |
|                     | Every file, with `--selective`              | Exits 1.                                                                           |
| [`diff`](#diff)     | Which component? (no name given)            | Shows every changed component.                                                     |
| [`remove`](#remove) | Remove it, though others depend on it?      | Exits 1. Add `--force` to remove it anyway.                                        |
|                     | Also remove orphaned dependencies?          | Removes them.                                                                      |
| [`eject`](#eject)   | Stop tracking it?                           | Exits 1. Add `--force` to eject it.                                                |

To get the same in a terminal, redirect the input, as in `npx @blotch/dolan update < /dev/null`. `init` also takes `--yes`.

## init

```bash
npx @blotch/dolan init
```

Asks two questions, then sets up the project. Pass an option to answer its question up front:

| Prompt                                 | Default             | Option         |
| -------------------------------------- | ------------------- | -------------- |
| Where should components be installed?  | `src/components/ui` | `--components` |
| Where should theme files be installed? | `src/styles`        | `--theme`      |

- Writes `dolan.config.json`. If one exists, it asks before overwriting (default No).
- Copies `default.css`, `dark.css` and `tailwind.css` into the theme folder, or `tailwind-plugin.ts` in place of `tailwind.css` for an app on Tailwind 3 (one with a `tailwind.config.*`, or without Tailwind 4 installed), with its test, `tailwind-plugin.test.ts`, if your `package.json` lists `@blotch/angular-lynx-testing-library` (see [add](#add)). If one is already there and differs, it asks before overwriting (default No) and keeps yours otherwise.
- Records the hashes of the theme files it copied in `dolan.lock.json`, so [`update`](#update) can tell whether you've edited them.
- Installs `@blotch/dolan` as a dependency if `package.json` doesn't list it, with your package manager. The copied components import its utilities. If the install fails, the next steps say how to run it.
- Creates the components folder and prints the next steps: the `@import` lines for the theme files (and, on Tailwind 3, the Tailwind plugin for your config), written relative to your global stylesheet (the first `styles` entry in `angular.json`, `src/styles.css` by default).

**Without a terminal**, or with `--yes`, `init` asks nothing:

- The folders come from `--components` and `--theme`, or are the defaults.
- Theme files that differ are kept, and `init` lists them. Add `--force` to replace them.
- An existing `dolan.config.json` stops `init` with exit code 1, before it changes anything. Add `--force` to overwrite it.

```bash
npx @blotch/dolan init --yes --components src/app/ui --theme src/app/theme
```

| Argument or option    | Description                                                                                         |
| --------------------- | --------------------------------------------------------------------------------------------------- |
| `--components <path>` | Install components here instead of asking.                                                          |
| `--theme <path>`      | Install the theme files here instead of asking.                                                     |
| `-y, --yes`           | Ask nothing: use the default folders, keep theme files that differ, and stop on an existing config. |
| `-f, --force`         | Overwrite an existing `dolan.config.json` and theme files without asking.                           |

## add

```bash
npx @blotch/dolan add [components...]
```

Copies each component into `<components>/<name>/`. With no names, it shows a checklist. Without a terminal, there's no checklist, so name the components.

- **Dependencies come too.** Adding `button` also adds `spinner`, and the CLI prints what it added.
- **Imports are rewritten.** `cn()` and the animation helpers are imported from `@blotch/dolan/utils/cn` and `@blotch/dolan/utils/animate`.
- **Unit tests are copied if you can run them.** A component's tests (`<name>.test.ts`, and one per other file it has) render it with `@blotch/angular-lynx-testing-library`, so they're copied only when your `package.json` lists the library. Otherwise `add` leaves the tests out and says so: run `ng generate @blotch/angular-lynx:add-testing`, then `dolan update` adds them. The tests' helpers come from `@blotch/dolan/testing/*`.
- **The tests cover the code fully.** Under `ng test --coverage`, each component's own tests cover all of its files, with nothing left out, so you can keep the copies in your coverage report and its thresholds.
- **Existing components are kept.** If a folder already exists, it asks before overwriting (default No) and skips it otherwise. Without a terminal it skips it, and says how to overwrite it. `--force` overwrites without asking. Overwriting also deletes the files an older version copied that the bundled source no longer has.
- **npm packages are installed.** If a component imports a package your `package.json` lacks, `add` installs it with your package manager (npm, pnpm, yarn or bun, detected from the lockfile): `class-variance-authority` for Alert, Badge, Button, Button Group, Toggle and Typography, and `@tanstack/charts` and `d3-shape` for `chart` and the chart presets.

| Argument or option | Description                                                                  |
| ------------------ | ---------------------------------------------------------------------------- |
| `[components...]`  | Component names. An unknown name stops the command and lists the valid ones. |
| `-f, --force`      | Overwrite installed components without asking.                               |

## list

```bash
npx @blotch/dolan list
```

Alias: `ls`. Prints each installed component with its status and file count. Only folders named after a known component count, so your own folders are ignored.

| Status     | JSON value      | Meaning                                                                |
| ---------- | --------------- | ---------------------------------------------------------------------- |
| up to date | `up-to-date`    | Your copy matches the bundled source.                                  |
| outdated   | `auto-update`   | You haven't edited it, and the bundled source changed or added a file. |
| modified   | `user-modified` | You edited it, and the bundled source hasn't changed.                  |
| conflict   | `conflict`      | Both changed, or dolan has no hash for a file that differs.            |

| Argument or option | Description                                                            |
| ------------------ | ---------------------------------------------------------------------- |
| `--json`           | Print `{ "components": [{ "name", "status", "fileCount" }] }` instead. |

## info

```bash
npx @blotch/dolan info <component>
```

Prints a component's files, the components it depends on, and the components that use it. With a `dolan.config.json`, it also shows what's installed. It works without one.

| Argument or option | Description         |
| ------------------ | ------------------- |
| `<component>`      | The component name. |

## diff

```bash
npx @blotch/dolan diff [component]
```

With a name, it prints every file that differs from the bundled source. Lines starting with `-` are yours, and lines starting with `+` are upstream. Without a name, it lists the changed components and asks which to show. Without a terminal, it shows them all.

| Argument or option | Description                         |
| ------------------ | ----------------------------------- |
| `[component]`      | Show this installed component only. |

## outdated

```bash
npx @blotch/dolan outdated
```

Lists the installed components that aren't up to date, using the [statuses](#list) above. It exits with code 1 when there are any, so a CI job can fail on it. Components you edited count as well.

| Argument or option | Description                                                    |
| ------------------ | -------------------------------------------------------------- |
| `--json`           | Print `{ "components": [...] }`, still exiting 1 if not empty. |

## update

```bash
npx @blotch/dolan update
```

Merges the bundled source into every installed component, file by file:

| Your file | Bundled source       | What `update` does                                                                            |
| --------- | -------------------- | --------------------------------------------------------------------------------------------- |
| Unchanged | Changed, or new file | Asks once whether to apply all of these (default Yes), then overwrites.                       |
| Unchanged | No longer has it     | Deletes it, with the changes above.                                                           |
| Edited    | Unchanged            | Keeps yours.                                                                                  |
| Edited    | Changed              | Conflict. Asks per file: show the diff, keep yours, take upstream, or review it hunk by hunk. |
| Edited    | No longer has it     | Conflict. Asks: show the diff, keep yours, or delete it.                                      |

- **No hash means conflict.** A file with no recorded hash that differs from upstream is a conflict. Theme files are the exception: `init` in 22.2.3 and earlier didn't record their hashes, so a theme file that's still exactly as one of those releases shipped it counts as unchanged.
- **Files the bundled source no longer has are deleted**, along with their lockfile entries. 22.2.3 stopped copying the `*-render.test.ts` files, for example. If you keep one you edited, it's yours: dolan stops tracking it.
- **Ejected components are left alone.** `update`, `list`, `diff` and `outdated` only look at the components in `dolan.lock.json`. See [`eject`](#eject).
- **Theme files** (`default.css`, `dark.css`, and `tailwind.css` or `tailwind-plugin.ts`, with `tailwind-plugin.test.ts` when you have the testing library) are merged the same way. Themes you made with [`theme`](#theme) aren't.
- **The theme follows a move between Tailwind versions.** After a [move to Tailwind 4](/guide/tailwindcss#move-to-tailwind-4), `update` copies `tailwind.css` and deletes `tailwind-plugin.ts` and its test, by the rules above: unchanged, they go with the other changes; edited, it asks. A move back to Tailwind 3 swaps them the other way. A plugin that an `init` from 22.2.3 or earlier copied counts as unchanged while it's exactly as that release shipped it. If you edited one of those, `update` can't tell it was dolan's and leaves it, and [`doctor`](#doctor) warns about it.

  ```text
  │  Shared files:
  │
  │    ✓ theme/default.css — up to date
  │
  │    ✓ theme/dark.css — up to date
  │
  │    + theme/tailwind.css — new file from upstream
  │
  │    − theme/tailwind-plugin.ts — the app uses Tailwind 4 → delete
  │
  │    − theme/tailwind-plugin.test.ts — the app uses Tailwind 4 → delete
  ```

- **New dependencies are added.** If a component's new version needs another component, `update` copies it in.
- **npm packages are installed** the same way [`add`](#add) does.
- **You're asked about a conflict once.** After you choose, the lockfile records the new upstream hash. If you kept your version, the file shows as modified until upstream changes again.
- **Without a terminal, conflicts wait for you.** `update` applies the auto-updates, but leaves each conflict's file and lockfile hash as they were, and exits with code 1. The next `update` in a terminal asks about them. Keeping your version instead would record the upstream hash, and you'd never be offered that change again. `--force` takes upstream's version of every conflict.

| Argument or option | Description                                                                                                              |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------ |
| `-f, --force`      | Overwrite every file with upstream, discarding your changes. Wins over `--selective`.                                    |
| `-s, --selective`  | Review every changed file one at a time, including your own edits. "Skip for now" asks again next run. Needs a terminal. |

## remove

```bash
npx @blotch/dolan remove <component>
```

Alias: `rm`. Deletes the component's folder and its lockfile entry.

- If other installed components depend on it, it warns and asks first (default No). Without a terminal, it stops with exit code 1 instead.
- It offers to remove dependencies that nothing else uses (default Yes). It looks one level deep, so remove deeper dependencies yourself. Without a terminal, it removes them.
- It doesn't uninstall npm packages.

| Argument or option | Description                                                                                 |
| ------------------ | ------------------------------------------------------------------------------------------- |
| `<component>`      | An installed component.                                                                     |
| `-f, --force`      | Skip both questions: remove it even if others depend on it, and remove unused dependencies. |

## eject

```bash
npx @blotch/dolan eject <component>
```

Removes the component from `dolan.lock.json` and leaves its files alone. It asks first (default No). Without a terminal, it stops with exit code 1 unless you pass `--force`.

The component is then yours: `update` doesn't touch it, even with `--force`, and `diff` and `outdated` skip it. `list` shows it as ejected. A component folder that isn't in `dolan.lock.json` counts as ejected, whatever put it there. To track it again, run `dolan add <component>`, which asks before overwriting it.

| Argument or option | Description                     |
| ------------------ | ------------------------------- |
| `<component>`      | An installed component.         |
| `-f, --force`      | Skip the confirmation question. |

## theme

```bash
npx @blotch/dolan theme [name]
```

Without a name, it lists the `.css` files in your theme folder. With a name, it copies `default.css` to `<theme folder>/<name>.css` for you to edit. It stops if that file exists.

Import the new file in place of `default.css`. See [Theming](/dolan/theming#start-a-new-theme).

| Argument or option | Description                         |
| ------------------ | ----------------------------------- |
| `[name]`           | Create a theme file with this name. |

## doctor

```bash
npx @blotch/dolan doctor
```

Runs these checks in order and exits with code 1 if any fail:

| Check                                                                                                                                        | If it doesn't pass |
| -------------------------------------------------------------------------------------------------------------------------------------------- | ------------------ |
| `dolan.config.json` exists, is valid JSON and has `components` and `theme` paths                                                             | Fails and stops    |
| The components and theme folders exist                                                                                                       | Fails              |
| The theme folder has `tailwind.css` (`tailwind-plugin.ts` on Tailwind 3), and `default.css` or `dark.css`                                    | Warns              |
| Each color the plugin maps with `themeColor()` has a matching `-rgb` twin in every theme file                                                | Warns              |
| The theme sets and maps the colors the installed components read, such as Glass's `glass-*` colors                                           | Warns              |
| `tailwindcss` is installed, and the app is set up for its version: no `tailwind.config.*` on Tailwind 4, a `tailwind.config.*` on Tailwind 3 | Warns              |
| No theme files for the other Tailwind version: `tailwind-plugin.ts` and its test on Tailwind 4, `tailwind.css` on Tailwind 3                 | Warns              |
| On Tailwind 4, the global stylesheet imports `tailwind.css`; on Tailwind 3, the Tailwind config mentions `blotchPlugin`                      | Warns              |
| `package.json` lists `@angular/core`, `@blotch/angular-lynx` and `@blotch/dolan`                                                             | Fails              |
| Every component folder is a known component, has all its files and has its dependencies                                                      | Warns              |
| No component has tests without `@blotch/angular-lynx-testing-library` to run them                                                            | Warns              |
| `package.json` lists the npm packages the components import, such as `class-variance-authority`                                              | Fails              |

It looks for `tailwindcss` the way the build does, from your app's folder, so it finds Tailwind that your workspace root installs, or that `@tailwindcss/postcss` brings when your `package.json` lists only that, and reports its version:

```text
◆  tailwindcss 4.3.3 found, set up for Tailwind 4
```

A `tailwind.config.*` with Tailwind 4 installed gets a warning: dolan sets the theme up for Tailwind 3 while the config is there (see [Move to Tailwind 4](/guide/tailwindcss#move-to-tailwind-4)). So does Tailwind 3 without a config, which the build needs to run it.

An ejected component's files aren't checked. A `utils` path in an older config is allowed but not needed. The `-rgb` twins are what [opacity modifiers](/dolan/theming#opacity-modifiers) such as `bg-primary/50` read; the check suggests the line to add for a missing one. A component's colors are missing from a theme copied before the component existed; the check quotes dolan's lines for them.

Options: none.
