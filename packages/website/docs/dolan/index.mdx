# UI Components

**UI components** are ready-made buttons, form controls, dialogs, charts and more for AngularLynx apps. A CLI copies their source into your project, so you own the code and can change anything. It's the same idea as [shadcn/ui](https://ui.shadcn.com/).

Two package names are involved:

- **`@blotch/ui`** is the component source. You never install it.
- **`@blotch/dolan`** is the CLI. It carries a copy of that source and writes it into `src/components/ui/`.

## Before you start

The components are styled with Tailwind CSS. If you said yes to Tailwind when you created the app, you're ready. Otherwise, set it up first: see [Tailwind CSS](/guide/tailwindcss).

## Installation

**1. Set up dolan.**

```bash
npx @blotch/dolan init
```

Press Enter to accept both default folders. It writes `dolan.config.json`, copies three theme files into `src/styles/`, and installs `@blotch/dolan` as a dependency:

- `default.css`: the light theme's colors and corner radius
- `dark.css`: the dark theme's colors
- `tailwind.css`: maps those colors to Tailwind classes such as `bg-primary`. An app on Tailwind 3 gets `tailwind-plugin.ts`, a Tailwind plugin, instead.

Copied components import `cn()` and animation helpers from `@blotch/dolan`, so your app needs it to build, not only to run commands. Once it's installed, `npx dolan` runs it too.

In CI, a script or an AI agent, `init` asks nothing and takes the default folders. Add `--yes` to skip the questions in a terminal too, and `--components` or `--theme` to choose other folders. See [`init`](/dolan/cli#init).

**2. Import the theme**, after Tailwind's own imports:

```css title="src/styles.css"
@layer theme, base, components, utilities;
@import 'tailwindcss/theme.css' layer(theme);
@import 'tailwindcss/utilities.css' layer(utilities);
@import './styles/default.css'; /* [!code highlight] */
@import './styles/dark.css'; /* [!code highlight] */
@import './styles/tailwind.css'; /* [!code highlight] */
```

`dark.css` changes nothing until you turn dark mode on. See [Theming](/dolan/theming#dark-mode).

**3. On Tailwind 3**, add the Tailwind plugin to your config instead, and import only the colors:

```typescript title="tailwind.config.ts"
import type { Config } from 'tailwindcss';
import preset from '@lynx-js/tailwind-preset';
import { blotchPlugin } from './src/styles/tailwind-plugin'; // [!code highlight]

const config: Config = {
  content: ['./src/**/*.{html,ts}'],
  presets: [preset],
  plugins: [blotchPlugin], // [!code highlight]
};

export default config;
```

```css title="src/styles.css"
@import './styles/default.css';
@import './styles/dark.css';

@tailwind base;
@tailwind utilities;
```

Put the `@import` lines first: CSS ignores an `@import` that comes after other rules.

**4. Add components.**

```bash
npx dolan add button card
```

Each one lands in `src/components/ui/<name>/`. Components it depends on come too: `button` brings `spinner`. So do the npm packages they import: `button` installs `class-variance-authority`.

**5. Use them.**

```typescript title="src/app/app.ts"
import { Component, signal } from '@angular/core';
import { LYNX_ELEMENTS } from '@blotch/angular-lynx';
import { UiButton } from '../components/ui/button';
import {
  UiCard,
  UiCardContent,
  UiCardHeader,
  UiCardTitle,
} from '../components/ui/card';

@Component({
  selector: 'app-root',
  imports: [
    LYNX_ELEMENTS,
    UiButton,
    UiCard,
    UiCardHeader,
    UiCardTitle,
    UiCardContent,
  ],
  template: `
    <view class="h-full bg-background p-6">
      <ui-card>
        <ui-card-header>
          <ui-card-title>Welcome</ui-card-title>
        </ui-card-header>
        <ui-card-content>
          <ui-button (pressed)="increment()">
            Tapped {{ count() }} times
          </ui-button>
        </ui-card-content>
      </ui-card>
    </view>
  `,
})
export class App {
  protected readonly count = signal(0);

  protected increment(): void {
    this.count.update((n) => n + 1);
  }
}
```

- The component pages import from `../components/ui/<name>`, a path relative to `src/app/`.
- Templates use [Lynx](/guide/glossary#lynx) **elements** such as `<view>` and `<text>` instead of HTML (see [Glossary](/guide/glossary#element)). Import `LYNX_ELEMENTS` whenever you use them (see [Elements](/api/angular-lynx/elements)).

## Good to know

- **Text color doesn't inherit.** CSS inheritance is off by default on Lynx, so put a color class such as `text-foreground` on each of your own `<text>` elements. The components color their own text.
- **Tests come with the code.** Once you've set up [testing](/guide/testing/) (`@blotch/angular-lynx-testing-library`), `dolan add` copies each component's tests too. They cover every line of the component under `ng test --coverage`, so the copies can stay in your coverage report.
- **Updates are merged, not forced.** Run [`dolan update`](/dolan/cli#update) after upgrading `@blotch/dolan`. It keeps your edits and asks when both sides changed.

## Components

**General**

- [Button](/dolan/button): a tappable button with variants, sizes and a loading state
- [Button Group](/dolan/button-group): connected buttons that act as one toolbar
- [Icon](/dolan/icon): 195 vector icons
- [Typography](/dolan/typography): text styles for headings, body and captions

**Layout**

- [Card](/dolan/card): a bordered surface with header, content and footer
- [Separator](/dolan/separator): a thin horizontal or vertical line
- [Accordion](/dolan/accordion): stacked sections that expand one or many at a time
- [Collapsible](/dolan/collapsible): one section that shows and hides its content
- [Tabs](/dolan/tabs): panels switched by a row of tab buttons
- [Aspect Ratio](/dolan/aspect-ratio): a box that keeps a width-to-height ratio
- [Scroll Area](/dolan/scroll-area): a scrolling container with edge events

**Liquid Glass**

- [Glass](/dolan/glass): Liquid Glass for floating controls, with each platform's fallback
- [Menu](/dolan/menu): a pull-down menu that grows out of its button
- [Context Menu](/dolan/context-menu): a menu that opens on a long press, lifting the element

**Navigation**

- [Nav Drawer](/dolan/nav-drawer): a side menu that slides in
- [Tab Bar](/dolan/tab-bar): tabs along the bottom that switch routed screens
- [Pagination](/dolan/pagination): page numbers with previous and next buttons

**Data Display**

- [Avatar](/dolan/avatar): a profile picture with a fallback
- [Badge](/dolan/badge): a small status label
- [List](/dolan/list): a fast, recycling list for long data
- [Chart](/dolan/chart): draws any TanStack Charts definition
- [Line Chart](/dolan/line-chart), [Area Chart](/dolan/area-chart), [Bar Chart](/dolan/bar-chart), [Scatter Chart](/dolan/scatter-chart) and [Candlestick Chart](/dolan/candlestick-chart): ready-made charts
- [Progress](/dolan/progress): a progress bar
- [Skeleton](/dolan/skeleton): a placeholder shape while content loads
- [Spinner](/dolan/spinner): a loading indicator
- [Empty State](/dolan/empty-state): a message for screens with nothing to show

**Forms**

- [Input](/dolan/input): a single-line text field with label, helper text and error
- [Textarea](/dolan/textarea): a multi-line text field that grows with its content
- [Label](/dolan/label): a caption for a form control
- [Checkbox](/dolan/checkbox): an on/off box with a check mark
- [Radio Group](/dolan/radio-group): pick one option from a list
- [Select](/dolan/select): pick one option from a bottom sheet
- [Switch](/dolan/switch): an on/off toggle switch
- [Toggle](/dolan/toggle): a button that stays pressed, alone or in a group

**Feedback**

- [Alert](/dolan/alert): an inline message
- [Alert Dialog](/dolan/alert-dialog): a dialog that asks for confirmation
- [Dialog](/dolan/dialog): a centered modal window
- [Bottom Sheet](/dolan/bottom-sheet): a panel that slides up from the bottom
- [Sheet](/dolan/sheet): a bottom sheet with header and footer slots
- [Action Sheet](/dolan/action-sheet): a list of actions that slides up
- [Toast](/dolan/toast): short messages that appear and go away

## Design principles

- **You own the code.** Components are plain files in your repo. Edit them like your own.
- **Signals throughout.** Inputs use `input()`, events use `output()`, and two-way values use `model()`, so `[(value)]` and `[(checked)]` work.
- **Theme tokens, not colors.** Components use classes such as `bg-primary` and `text-muted-foreground`, defined once in your theme. See [Theming](/dolan/theming).
- **Variants with `cva`.** Variant classes come from [class-variance-authority](https://cva.style/). Components export them, for example `buttonVariants`.
- **Your classes win.** Most components take a `class` input. It's merged with `cn()`, so a conflicting class you pass replaces the default.
- **Lynx elements only.** Components are built from `<view>`, `<text>`, `<svg>`, `<overlay>` and other Lynx elements, never HTML.
