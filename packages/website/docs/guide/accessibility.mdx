# Accessibility

Screen readers read your app aloud and let people move through it by touch: **VoiceOver** on iPhone and **TalkBack** on Android. [Lynx](/guide/glossary#lynx) elements take attributes that tell the screen reader what each element is and what to say.

## `id`, `a11y-id` and `name`

Three attributes name an element, and they're often confused:

| Attribute | What it's for                                                                                                             |
| --------- | ------------------------------------------------------------------------------------------------------------------------- |
| `id`      | The element's unique name on the page. `accessibility-elements` and `requestFocus('#id')` use it                          |
| `a11y-id` | A second name that only accessibility uses. `accessibility-elements-a11y` lists these, and several elements can share one |
| `name`    | Lets native code in the [host app](/guide/glossary#host-app) find the view. Accessibility doesn't use it                  |

Use `id` unless you have a reason not to.

## Label an element

```angular-html
<view
  [accessibility-element]="true"
  accessibility-traits="button"
  accessibility-label="Add to favorites"
  (bindtap)="favorite()"
>
  <image src="assets/heart.png" class="h-6 w-6" />
</view>
```

- **`<text>` and `<image>` are read by default.** A `<text>` reads its own text, so most text needs nothing extra.
- **`[accessibility-element]="true"` makes an element one stop** for the screen reader. Use it on a `<view>` that acts as a button or groups related content.
- **`accessibility-label` is what gets read.** Give one to anything without readable text, such as an icon button.
- **`accessibility-traits` says what kind of thing it is,** such as `button`, `image`, `link` or `header`. Note the plural: Lynx ignores `accessibility-trait`. iOS takes several, separated by commas with no spaces, such as `button,selected`; Android reads only one.
- **An active `routerLinkActive` link is `selected` for you.** `LYNX_ELEMENTS` adds the trait while its route is active, after the element's own traits. See [Routing](/guide/routing#navigate-between-screens).

## Set the reading order

```angular-html
<view accessibility-elements="title,price,buy">
  <text id="price" [accessibility-element]="true">$12</text>
  <text id="title" [accessibility-element]="true">Blue mug</text>
  <view
    id="buy"
    [accessibility-element]="true"
    accessibility-traits="button"
    accessibility-label="Buy"
    (bindtap)="buy()"
  ></view>
</view>
```

- **Screen readers go top to bottom, then left to right,** by default.
- **`accessibility-elements` lists child `id`s, separated by commas,** in the order to read them. The example reads the title before the price.
- **Children not in the list can't be focused** once a parent sets it.
- **`accessibility-elements-a11y`** does the same with `a11y-id`s.

## Hide decoration

```angular-html
<view [accessibility-elements-hidden]="true">
  <image src="assets/confetti.png" class="h-24 w-full" />
</view>
```

`[accessibility-elements-hidden]="true"` hides an element and everything inside it from the screen reader.

## Keep focus inside a dialog

```angular-html
<overlay [attr.visible]="open()">
  <view class="flex h-full w-full items-center justify-center bg-black/50">
    <view
      class="w-4/5 rounded-lg bg-background p-6"
      [accessibility-exclusive-focus]="true"
    >
      <text class="text-lg text-foreground">Delete this item?</text>
      <view
        [accessibility-element]="true"
        accessibility-traits="button"
        accessibility-label="Cancel"
        (bindtap)="open.set(false)"
      >
        <text>Cancel</text>
      </view>
    </view>
  </view>
</overlay>
```

With `[accessibility-exclusive-focus]="true"`, the screen reader moves only between the elements inside it. People can't swipe out of the dialog to the page behind. See [Dialogs and overlays](/guide/overlays).

## Announce changes and move focus from code

Some changes don't move the screen reader, such as a cart count going up. Tell people about them with `LynxAccessibility`:

```typescript title="src/app/cart.ts"
import { Component, inject, signal } from '@angular/core';
import { LYNX_ELEMENTS, LynxAccessibility } from '@blotch/angular-lynx';

@Component({
  selector: 'app-cart',
  imports: [LYNX_ELEMENTS],
  template: `
    <view
      [accessibility-element]="true"
      accessibility-traits="button"
      accessibility-label="Add to cart"
      (bindtap)="add()"
    >
      <text>Add to cart</text>
    </view>
    <text id="total">{{ count() }} items</text>
  `,
})
export class Cart {
  readonly #a11y = inject(LynxAccessibility);
  readonly count = signal(0);

  add(): void {
    this.count.update((n) => n + 1);
    this.#a11y.announce(`${this.count()} items in cart`).catch(() => {});
  }
}
```

- **`announce(text)`** makes the screen reader speak, without moving focus.
- **`requestFocus('#id')`** moves the screen reader to the element with that `id`, such as `requestFocus('#total')`.
- **Both return a Promise** that rejects where Lynx can't do it, such as in the [web preview](/guide/glossary#web-preview). The `catch` keeps that quiet.

The signatures are in the [API reference](/api/angular-lynx/accessibility).

## Check it in unit tests

The [testing library](/guide/testing/)'s queries read these attributes, so a test finds an element the way a screen reader does:

```typescript title="src/app/cart.test.ts"
const { getByRole } = await render(Cart);

fireEvent.tap(getByRole('button', { name: 'Add to cart' }));
```

`getByRole` finds a `<view>` only with `[accessibility-element]="true"`, so a missing one fails the test. See [`*ByRole`](/api/testing-library/#byrole) and [`*ByAccessibilityLabel`](/api/testing-library/#byaccessibilitylabel).

## Test with a screen reader

**On an iPhone:**

1. Open **Settings → Accessibility → VoiceOver** and turn it on.
2. Swipe right or left to move between elements. Double-tap anywhere to tap the selected one.
3. To toggle it quickly, set **Settings → Accessibility → Accessibility Shortcut** to VoiceOver, then triple-click the side button.

VoiceOver doesn't run in the iOS [Simulator](/guide/glossary#simulator), the virtual iPhone on your Mac. Instead, open **Accessibility Inspector** from Xcode's **Xcode → Open Developer Tool** menu and point it at the Simulator. It shows the label and traits of each element you hover.

**On Android:**

1. Open **Settings → Accessibility → TalkBack** and turn it on. On some phones, it's under **Installed apps** or **Downloaded apps** in that menu.
2. Swipe right or left to move between elements. Double-tap to tap the selected one.

TalkBack also runs in the Android [emulator](/guide/glossary#emulator), the virtual Android phone on your computer. Drag with the mouse to swipe. If its Settings has no TalkBack, install **Android Accessibility Suite** from the Play Store, which needs an emulator image with Google Play.

You can test either way in [Lynx Explorer](/guide/glossary#lynx-explorer) or in your own app. AngularLynx turns on Lynx's accessibility support in every build, so there's nothing to enable.

## Common attributes

| Attribute                       | Value                        | Effect                                                            |
| ------------------------------- | ---------------------------- | ----------------------------------------------------------------- |
| `accessibility-element`         | `true` / `false`             | Makes the element one stop for the screen reader                  |
| `accessibility-label`           | text                         | What the screen reader reads                                      |
| `accessibility-traits`          | `button`, `image`, `link`, … | What kind of element it is                                        |
| `accessibility-value`           | text                         | A current value read after the label, such as a slider's position |
| `accessibility-elements`        | comma-separated `id`s        | Reading order of the children                                     |
| `accessibility-elements-a11y`   | comma-separated `a11y-id`s   | The same, by `a11y-id`                                            |
| `accessibility-elements-hidden` | `true` / `false`             | Hides the element and its children                                |
| `accessibility-exclusive-focus` | `true` / `false`             | Keeps focus inside the element                                    |

The full list, with platform support, is in the [accessibility API reference](/api/angular-lynx/accessibility).
