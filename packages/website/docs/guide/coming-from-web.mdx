# Coming from web Angular

This page lists everything that changes when you move Angular code from the browser to Lynx. Skim the cheat sheet first, then check the compatibility table for the features you use.

## Cheat sheet

| On the web                                              | On Lynx                                                                                 |
| ------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| `<div>`                                                 | `<view>`. A `<div>` renders as one                                                      |
| `<span>`, `<p>`, `<h1>`                                 | `<text>`. They render as one. Style text on the `<text>` that holds it                  |
| `<img src>`                                             | `<image src>`, which needs a width and height. An `<img>` renders as one, sized to fit  |
| A scrolling `<div>`                                     | `<scroll-view>`, or `<list>` for long lists                                             |
| `<button (click)>`                                      | `<view (bindtap)>` with a `<text>` inside. A `<button>` renders as a `<text>` that taps |
| `<input (input)>`                                       | `<input (bindinput)>`, with the value in `$event.detail.value`. `(input)` works too     |
| `(click)`                                               | `(bindtap)`, or `(catchtap)` to stop it bubbling. `(click)` works too                   |
| `:root { --x: … }`                                      | `page { --x: … }`                                                                       |
| `display: block`                                        | `display: linear`, the default. `display: block` becomes it                             |
| `:hover`, `@media`                                      | No equivalent. Use signals, and `LynxSystemInfo` for screen size                        |
| `bootstrapApplication` from `@angular/platform-browser` | `bootstrapApplication` from `@blotch/angular-lynx`                                      |
| Zone.js or zoneless                                     | Zoneless only                                                                           |
| `<a routerLink>`                                        | `routerLink` on any element, `<a>` included                                             |
| `document`, `window`                                    | Not available                                                                           |

## Your web templates render

<Go example="web-tags" defaultFile="src/app/app.ts" />

AngularLynx renders common HTML tags as the Lynx element they stand for, so a template written for the browser shows up on a phone:

- **Block tags render as a `<view>`:** `<div>`, `<section>`, `<ul>`, `<li>` and the like.
- **Text tags render as a `<text>`:** `<span>`, `<p>`, `<h1>`, `<a>`, `<button>`, `<label>` and the like.
- **`<img>` renders as an `<image>`** that takes its picture's size until CSS gives it one.
- **Text straight inside a block tag shows,** in a plain `<text>` of its own.
- **DOM events that Lynx also sends run,** such as `(click)`, `(input)` and `(keyup.enter)`.

It gets ported code on screen, but it isn't a browser. [HTML tags](/guide/elements/#html-tags) lists what carries over and what doesn't. Write Lynx elements in new code: they have every attribute, and typed events.

Here's one component in each:

```angular-html
<!-- Web -->
<div class="card" (click)="select()">
  <img [src]="avatar" />
  <span>{{ name() }}</span>
</div>

<!-- Lynx -->
<view class="card" (bindtap)="select()">
  <image [src]="avatar" class="w-10 h-10" />
  <text>{{ name() }}</text>
</view>
```

## Templates

**Lynx elements replace HTML.** A Lynx app has no HTML engine. Lynx [elements](/guide/elements/) map to native UI controls instead, and AngularLynx renders common HTML tags as the closest one. [Elements and layout](/guide/elements/) lists them all.

**Text belongs in `<text>`.** On the web, text can sit anywhere. On Lynx, only a `<text>` draws it. Text written straight in a `<view>` or `<div>` still shows, because AngularLynx draws it in a plain `<text>` of its own. But the `<view>`'s text styles don't reach it, and it takes a line of its own. Put text you style in a `<text>`, and nest `<text>` elements to style part of a sentence.

**Import `LYNX_ELEMENTS`.** Add it to every component that uses Lynx elements, as `ng generate component` does. It gives you type checking in your editor and makes `ng test` compile.

```typescript
import { Component } from '@angular/core';
import { LYNX_ELEMENTS } from '@blotch/angular-lynx';

@Component({
  selector: 'app-hello',
  imports: [LYNX_ELEMENTS],
  template: `<view><text>Hello</text></view>`,
})
export class Hello {}
```

## Events

Lynx events start with `bind` or `catch`:

- `(bindtap)` handles a tap and lets it bubble up to parent elements.
- `(catchtap)` handles a tap and stops it there.

Event data is in `$event.detail`. A text input's value, for example, is `$event.detail.value`.

DOM event names work where Lynx sends the same event. `(click)` runs on a tap, `(input)` when the text changes, and `(keyup.enter)` when the keyboard's return key is pressed. A text field's value is in `$event.target.value` too, as on the web. Names Lynx has no event for, such as `(mouseover)`, never run.

A handler can do anything it would on the web, such as navigate or open an overlay.

See [Handling taps and events](/guide/elements/event-handling) for every event.

## Styling

Lynx has its own CSS engine. It supports most layout CSS, but its defaults differ from a browser's:

- **Elements stack vertically** by default (`display: linear`). Add `display: flex` (Tailwind's `flex`) for flexbox.
- **`box-sizing` is `border-box`**, and margins don't collapse.
- **Styles aren't inherited.** Setting `color` on a `<view>` doesn't color the `<text>` inside it.
- **`rem` is 14px**, not 16px.
- **Some features are missing:** `:hover`, `::before`, `@media` and `!important`.

[CSS on Lynx](/guide/styling) covers every difference. [Tailwind CSS](/guide/tailwindcss) 4 works as on the web: the build adapts its CSS for Lynx.

## The JavaScript environment

Your code doesn't run in a browser. There's no DOM, so `document.querySelector`, `document.createElement` and `localStorage` don't exist. AngularLynx fills in what Angular itself needs, such as `setTimeout` and `URL`, and `document:` and `window:` listeners hear touches anywhere on screen.

Libraries that touch the DOM, or depend on browser APIs, won't work. That includes Angular Material, most of the CDK, and chart libraries that draw on a 2D `<canvas>`. 3D libraries that draw with WebGL2, such as three.js and angular-three, work in a [`<canvas>`](/api/elements/canvas). [The JavaScript environment](/guide/concepts/javascript-environment) lists what's available.
