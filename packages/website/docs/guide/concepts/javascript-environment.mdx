# The JavaScript environment

Your app's JavaScript runs in Lynx's engine, not in a browser. Standard JavaScript works, but browser APIs mostly don't. This page lists what's there, what's missing, and what to use instead.

## What AngularLynx adds for you

Lynx doesn't provide some APIs that Angular relies on. AngularLynx adds them before your app starts:

- `setTimeout`, `setInterval`, `clearTimeout`, `clearInterval`
- `requestAnimationFrame`, `requestIdleCallback`
- `queueMicrotask`, `AbortController`
- `URL`, `URLSearchParams`
- `fetch`, `XMLHttpRequest`, `Headers`, `Request`, `Response`
- `TextEncoder`, `TextDecoder` (UTF-8 only), `DOMException`
- Newer built-in methods, up to ES2026, such as `array.at()`, `toSorted()` and `Object.groupBy()`: see [JavaScript language level](#javascript-language-level)

It also adds small `document`, `window` and `navigator` objects, with only what Angular reads internally. They are not a DOM: `document.querySelector()` always returns `null`.

## What's missing, and what to use instead

| Browser API                                                  | On Lynx                                                                                       |
| ------------------------------------------------------------ | --------------------------------------------------------------------------------------------- |
| The DOM: `querySelector`, `createElement`, `innerHTML`       | Use templates, `viewChild()` and signals                                                      |
| `getBoundingClientRect()`, `getComputedStyle()`              | [Call element methods](/guide/selector-query), or a [main-thread script](/guide/main-thread/) |
| `IntersectionObserver`                                       | [Detect when elements are visible](/guide/exposure)                                           |
| `window.addEventListener('resize')`, `matchMedia`            | [`LynxSystemInfo`](/api/angular-lynx/system-info) for screen size                             |
| `navigator.userAgent`, `navigator.language`                  | [`LynxSystemInfo`](/api/angular-lynx/system-info), [`LynxLocale`](/api/angular-lynx/locale)   |
| `localStorage`, `sessionStorage`                             | See [Storage](#storage)                                                                       |
| `WebSocket`                                                  | See [Network requests](#network-requests)                                                     |
| `Intl`                                                       | See [Intl](#intl)                                                                             |
| `performance.now()`                                          | `Date.now()`. To trace performance, see [Profiling](/guide/profiling)                         |
| `<canvas>`, Web Audio, Web Workers, clipboard, drag and drop | Not available                                                                                 |

Code that calls a missing API throws when it runs. That includes code inside libraries. Before adding an npm package, check that it doesn't use the DOM.

## Network requests

`HttpClient`, `httpResource`, `fetch` and `XMLHttpRequest` work. [Load data from a server](/guide/http) shows how, and what's different on a device.

Lynx itself can make requests only from the [background thread](/guide/concepts/threads). The `fetch` and `XMLHttpRequest` AngularLynx adds pass each request there and bring the response back.

Lynx has no `WebSocket`.

## Timers

`setTimeout` and the other timer functions work. When the user switches to another app, Lynx pauses JavaScript, so a timer can fire late after the app comes back. Don't use timers to measure elapsed time; compare `Date.now()` values instead.

## Storage

There's no `localStorage`. To share values between the pages of your app while it runs, use [`LynxSessionStorage`](/guide/session-storage). To keep data after the app closes, store it in the host app and reach it through a [native module](/api/angular-lynx/native-module).

## Intl

Lynx has no `Intl` object. Libraries that call `Intl.DateTimeFormat`, `Intl.NumberFormat` or `Intl.PluralRules` throw on Lynx. Add the [FormatJS polyfills](https://formatjs.github.io/docs/polyfills) for the parts you use. [Internationalization](/guide/i18n) shows the setup.

Angular's own pipes, such as `DatePipe` and `CurrencyPipe`, use Angular's locale data instead of `Intl`, so they work.

## URL

`URL` and `URLSearchParams` work, because AngularLynx provides them. There's no `window.location` and no address bar: the router keeps its URL in memory. See [Routing](/guide/routing).

## JavaScript language level

Write modern TypeScript as usual. The build compiles new syntax, such as `?.` and `??`, down to what Lynx supports.

Lynx's engine has fewer built-in methods than a browser: the main thread supports ES2019 and some later additions. AngularLynx adds the rest, up to ES2026, before your app starts. So your code and libraries written for current browsers can call them:

```ts
const last = items.at(-1);
const cheapest = items.toSorted((a, b) => a.price - b.price);
const byStatus = Object.groupBy(orders, (order) => order.status);
const shared = new Set(mine).intersection(new Set(theirs));
const firstTen = users
  .values()
  .filter((user) => user.active)
  .take(10)
  .toArray();
```

These are still missing, because they need the engine itself, or they're browser APIs rather than JavaScript:

| Missing                                                          | Use instead                                        |
| ---------------------------------------------------------------- | -------------------------------------------------- |
| The `d` and `v` regular expression flags                         | Patterns without them                              |
| `new Error(message, { cause })`                                  | Set `error.cause` after creating the error         |
| `JSON.rawJSON()`, and `context.source` in a `JSON.parse` reviver | Not available                                      |
| Resizable `ArrayBuffer`s, `transfer()`, `Float16Array`           | Not available                                      |
| `structuredClone(value)`                                         | `JSON.parse(JSON.stringify(value))` for plain data |
| `atob()`, `btoa()`                                               | `Uint8Array.fromBase64()`, `bytes.toBase64()`      |

:::warning A missing method can blank the whole screen
If a template or a `computed()` calls something that's missing, the render fails, and nothing on screen updates. The error is "not a function" or "is not defined". It's not about signals.
:::

:::warning `for await` over an array of promises
On the main thread, `for await (const value of promises)` gives you each promise, not its value. Await each one yourself, or use `await Promise.all(promises)`. Async generators work as usual.
:::
