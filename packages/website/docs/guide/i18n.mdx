# Internationalization

Translate your app with Angular's `@angular/localize`. Mark text with `i18n` or `$localize`, extract it with `ng extract-i18n`, and load the right translation when the app starts. One [bundle](/guide/glossary#bundle) serves every language.

<Go example="i18n" defaultFile="src/app/app.ts" />

## What's different on Lynx

- **Translations load at runtime.** Angular's build-time translation, with one build per language, isn't supported. Your app calls `loadTranslations()` before it starts.
- **The language comes from the host app.** AngularLynx reads `appLocale` from the [host app](/guide/glossary#host-app)'s [GlobalData](/guide/glossary#globaldata). The iOS and Android apps that [`ng build --platform`](/guide/native-apps) generates send the phone's language as a tag such as `'fr-FR'`. Lynx Explorer sends none, so there your app uses the `sourceLocale` from angular.json.
- **Lynx has no `Intl`.** `$localize` and Angular's pipes don't need it. For code that calls `Intl`, the build can [add the APIs it uses](#use-intl).
- **Switching language means restarting the app**, for most text. Template `i18n` text and `LOCALE_ID` don't change after they're first used. Some strings [can switch live](#switch-language-while-the-app-runs).

## Set up

```bash
ng generate @blotch/angular-lynx:add-i18n
```

This command:

- installs `@angular/localize`, at the same version as `@angular/core`
- adds `"i18n": { "sourceLocale": "en-US" }` to your project in angular.json
- adds `@angular/localize/init` to the build's `polyfills`, so `$localize` exists before your code runs
- adds `@angular/localize` to `types` in tsconfig.app.json, so TypeScript knows `$localize`
- adds `provideLocale()` to your app config
- sets up `ng extract-i18n` to write your messages as JSON to `src/locale`

```typescript title="src/app/app.config.ts"
import {
  type ApplicationConfig,
  provideZonelessChangeDetection,
} from '@angular/core';
import {
  provideLocale,
  provideRenderer,
  provideRouter,
} from '@blotch/angular-lynx';
import { routes } from './app.routes';

export const appConfig: ApplicationConfig = {
  providers: [
    provideLocale(), // [!code highlight]
    provideZonelessChangeDetection(),
    provideRenderer(),
    provideRouter(routes),
  ],
};
```

`provideLocale()` sets Angular's `LOCALE_ID` from `appLocale`, falling back to `sourceLocale`, then to `en-US`. It also falls back, and logs a warning, when Angular has no locale data for `appLocale`: Angular's date and number pipes would throw for it. So a phone set to a language your app doesn't support gets your source language, as a native app does. Register the data of each language you support with [`registerLocaleData()`](https://angular.dev/api/common/registerLocaleData).

## Mark text for translation

```typescript title="src/app/greeting.ts"
import { Component, computed, signal } from '@angular/core';
import { LYNX_ELEMENTS } from '@blotch/angular-lynx';

@Component({
  selector: 'app-greeting',
  imports: [LYNX_ELEMENTS],
  template: `
    <text i18n="@@greeting">Hello, world!</text>
    <text>{{ welcome() }}</text>
  `,
})
export class Greeting {
  readonly userName = signal('Ada');
  readonly welcome = computed(
    () => $localize`:@@welcome:Welcome, ${this.userName()}:userName:!`,
  );
}
```

- **`i18n`** on an element marks its text for translation. `@@greeting` sets the message ID.
- **`$localize`** marks a string in TypeScript. `:@@welcome:` sets its ID, and `:userName:` names the placeholder for `${this.userName()}`.
- **Give every message an `@@` ID.** Translation files are keyed by ID, and a custom ID stays the same when you edit the English text.

## Extract the messages

```bash
ng extract-i18n
```

It writes `src/locale/messages.json` with every message in your source language:

```json title="src/locale/messages.json"
{
  "locale": "en-US",
  "translations": {
    "greeting": "Hello, world!",
    "welcome": "Welcome, {$userName}!"
  }
}
```

Copy it to one file per language, such as `messages.fr.json`, and translate the values. Keep placeholders like `{$userName}` as they are.

{/* cspell:ignore Bonjour Bienvenue Français */}

```json title="src/locale/messages.fr.json"
{
  "locale": "fr",
  "translations": {
    "greeting": "Bonjour le monde !",
    "welcome": "Bienvenue, {$userName} !"
  }
}
```

The JSON format's `translations` object is exactly what `loadTranslations()` takes. That's why `add-i18n` picks it over Angular's default, XLIFF. To extract XLIFF for a translation tool, pass `--format xlf`, then convert each translated file to an object yourself.

`ng extract-i18n` takes [Angular's options](https://angular.dev/cli/extract-i18n). `add-i18n` sets two of them on the `extract-i18n` target in angular.json:

```json title="angular.json"
"extract-i18n": {
  "builder": "@blotch/angular-lynx-build:extract-i18n",
  "options": {
    "format": "json",
    "outputPath": "src/locale"
  }
}
```

The builder runs Angular's own extractor. Angular CLI can't pick an extractor for the AngularLynx build by itself, so an app needs this target. `ng add` writes it, and `ng update @blotch/angular-lynx` adds it to apps made with 22.2.2 or older.

## Load a translation

Call `loadTranslations()` in main.ts, before `bootstrapApplication()`:

```typescript title="src/main.ts"
import { loadTranslations } from '@angular/localize';
import { bootstrapApplication, getLynxAppLocale } from '@blotch/angular-lynx';
import { App } from './app/app';
import { appConfig } from './app/app.config';
import fr from './locale/messages.fr.json';

if (getLynxAppLocale()?.startsWith('fr')) {
  loadTranslations(fr.translations);
}

bootstrapApplication(App, appConfig);
```

- **`getLynxAppLocale()`** reads `appLocale` without Angular's dependency injection, so it works before the app starts. It returns `undefined` when the host app hasn't set one.
- **Match the language, not the whole tag.** The phone may say `'fr-FR'`, `'fr-CA'` or `'fr'`.
- **Load before bootstrap.** Angular translates template text and `$localize` strings when it creates each component, using whatever was loaded at that moment.
- **Messages without a translation** show the source text and log a warning.

## Read the current locale

Inject `LynxLocale` for the locale as a signal:

```typescript title="src/app/locale-badge.ts"
import { Component, inject } from '@angular/core';
import { LYNX_ELEMENTS, LynxLocale } from '@blotch/angular-lynx';

@Component({
  selector: 'app-locale-badge',
  imports: [LYNX_ELEMENTS],
  template: `<text>Locale: {{ locale.locale() }}</text>`,
})
export class LocaleBadge {
  readonly locale = inject(LynxLocale);
}
```

`locale()` returns `appLocale` as the host app sent it, or else `sourceLocale`, then `en-US`. Angular's pipes use `LOCALE_ID` instead, which also falls back when Angular has no data for `appLocale` (see [Set up](#set-up)). To format dates, numbers or currency for a locale other than `en-US`, register its data with [`registerLocaleData()`](https://angular.dev/api/common/registerLocaleData).

## Switch language while the app runs

A `$localize` string inside a `computed()` can switch live. Make it depend on a signal, then replace the translations and change the signal:

```typescript title="src/app/language-picker.ts"
import { Component, computed, signal } from '@angular/core';
import { clearTranslations, loadTranslations } from '@angular/localize';
import { LYNX_ELEMENTS } from '@blotch/angular-lynx';
import fr from '../locale/messages.fr.json';

@Component({
  selector: 'app-language-picker',
  imports: [LYNX_ELEMENTS],
  template: `
    <text>{{ greeting() }}</text>
    <view (bindtap)="use('fr')"><text>Français</text></view>
    <view (bindtap)="use('en')"><text>English</text></view>
  `,
})
export class LanguagePicker {
  readonly #language = signal('en');
  readonly greeting = computed(() => {
    this.#language(); // re-run when the language changes
    return $localize`:@@greeting:Hello, world!`;
  });

  use(language: string): void {
    clearTranslations();
    if (language === 'fr') {
      loadTranslations(fr.translations);
    }
    this.#language.set(language);
  }
}
```

Template `i18n` text, `$localize` strings outside a `computed()`, and `LOCALE_ID` keep the language the app started with. To change those, the app has to start again with the new `appLocale`.

## Use `Intl`

Lynx has no `Intl` where your app runs. `new Intl.DisplayNames()` throws on a phone, while your tests, which run in Node, pass. The methods that would use `Intl` ignore the locale: `toLocaleString()` formats numbers the `en-US` way and dates as `01/15/2026, 01:05:09 PM`, and `localeCompare()` compares character codes, so `'é'` sorts after `'z'`.

List the `Intl` APIs your code uses in the build's `intl` option:

```json title="angular.json"
"build": {
  "builder": "@blotch/angular-lynx-build:application",
  "options": {
    "intl": ["DisplayNames", "NumberFormat", "Collator"]
  }
}
```

Then install the [FormatJS polyfills](https://formatjs.github.io/docs/polyfills) they use. The build stops and lists the ones that are missing. For the three above:

```bash
npm install @formatjs/intl-getcanonicallocales @formatjs/intl-locale @formatjs/intl-displaynames @formatjs/intl-numberformat @formatjs/intl-pluralrules
```

The build adds them to the bundle for iOS and Android, before your code, on both [threads](/guide/concepts/threads). The web preview uses the browser's own `Intl`, so its bundle doesn't change. Code you share with a web app then works as it is:

```typescript title="src/app/countries.ts"
export const regionName = (code: string, locale: string): string =>
  new Intl.DisplayNames([locale], { type: 'region', fallback: 'none' }).of(
    code,
  ) ?? code;

export const sortedCountries = (codes: string[], locale: string) =>
  codes
    .map((code) => ({ code, name: regionName(code, locale) }))
    .sort((a, b) => a.name.localeCompare(b.name, locale));
```

| `intl` entry         | Adds                                                                                                    | Package                             |
| -------------------- | ------------------------------------------------------------------------------------------------------- | ----------------------------------- |
| `Collator`           | `Intl.Collator`, and `localeCompare()` with locales and options                                         | None: AngularLynx's own (see below) |
| `DateTimeFormat`     | `Intl.DateTimeFormat`, and `toLocaleString()`, `toLocaleDateString()`, `toLocaleTimeString()` on dates  | `@formatjs/intl-datetimeformat`     |
| `DisplayNames`       | `Intl.DisplayNames`: the names of regions, languages, scripts and currencies                            | `@formatjs/intl-displaynames`       |
| `ListFormat`         | `Intl.ListFormat`                                                                                       | `@formatjs/intl-listformat`         |
| `NumberFormat`       | `Intl.NumberFormat`, with compact, currency, percent and unit styles, and `toLocaleString()` on numbers | `@formatjs/intl-numberformat`       |
| `PluralRules`        | `Intl.PluralRules`                                                                                      | `@formatjs/intl-pluralrules`        |
| `RelativeTimeFormat` | `Intl.RelativeTimeFormat` ("in 3 days")                                                                 | `@formatjs/intl-relativetimeformat` |

Every entry also needs `@formatjs/intl-getcanonicallocales` and `@formatjs/intl-locale`, which add `Intl.getCanonicalLocales()` and `Intl.Locale`. Some need others too, which the build adds for you: `NumberFormat` uses `PluralRules`, and `DateTimeFormat` and `RelativeTimeFormat` use `NumberFormat`.

### Locales

- **The build adds the data of your app's locales:** `i18n.sourceLocale` and each locale in `i18n.locales` in angular.json. One bundle serves every language, so it holds them all. A locale FormatJS has no data for gets a warning, and formats in your source locale.
- **Without a locale,** as in `new Intl.NumberFormat()` or `n.toLocaleString()`, they use the phone's language (`appLocale`) when it's one of your locales, and your source locale otherwise. That's how [`provideLocale()`](#set-up) picks Angular's `LOCALE_ID`. Lynx Explorer sends no `appLocale`, so there it's always your source locale.

### Time zones

Dates format in the phone's time zone, as in a browser. The build reads the zone's offsets from the device's clock, summer time included. The apps `ng build --platform` makes also send the zone's name as `appTimeZone`, so `resolvedOptions().timeZone` is, for example, `'Europe/Paris'`, and `timeZoneName: 'long'` gives `Central European Summer Time`. Lynx Explorer sends no name, so there the zone is `'Etc/Unknown'`, and its name shows as an offset, such as `GMT+02:00`.

`timeZone: 'UTC'` and offsets such as `timeZone: '+05:30'` work as they are. Other zones, such as `timeZone: 'America/New_York'`, need FormatJS's time zone data. Add it to `polyfills`:

```json title="angular.json"
"polyfills": ["@formatjs/intl-datetimeformat/add-golden-tz.js"]
```

It adds about 1.6 MB to the bundle, and to the web preview's too, where it does nothing.

### Sorting

FormatJS has no `Intl.Collator`, so the `Collator` entry is AngularLynx's own. When you build, it asks Node, which has the full ICU library browsers sort with, how each of your locales orders the letters of Latin, Greek, Cyrillic, Armenian, Hebrew, Arabic, Devanagari, Thai and Japanese kana, the punctuation and symbols, and their accents and cases. Then it sorts with that, as the [Unicode Collation Algorithm](https://www.unicode.org/reports/tr10/) does: by letter, then accent, then case. That includes each language's own letters, such as Swedish `ä` after `z`, Spanish `ñ` after `n` and Czech `ch` after `h`, and the `numeric`, `sensitivity`, `caseFirst` and `ignorePunctuation` options. On every pair of 120 test words in 10 languages, it orders them as Node does.

What's approximate:

- **Chinese, Japanese and Korean ideographs and syllables** sort after the other scripts, by Unicode code point. There's no pinyin or stroke order.
- **Contractions of three letters or more,** such as Hungarian `dzs`, sort as their letters. So do Thai's vowels that come before a consonant.
- **Text written as a letter plus a separate accent** (`a` + U+0308) sorts as the letter, in a language that makes the accented letter one of its own, as Swedish does `ä`. A phone's keyboard types an accented letter as one character, so this is rare.
- **`usage: 'search'`** compares as `'sort'` does, and the `collation` option (`'phonebk'`, `'pinyin'`) is ignored: `resolvedOptions().collation` is always `'default'`.

### Bundle size

`Intl` data is large, so add only what your code uses. Each API's code and data go into both threads' halves of the bundle, so they count twice in its size. Measured as what each adds to the iOS and Android bundle:

| `intl` entry                               | Adds, with one locale | Adds for each more locale                                                        |
| ------------------------------------------ | --------------------- | -------------------------------------------------------------------------------- |
| `Collator`                                 | 630 kB                | Up to 40 kB, for a language that orders its letters its own way, such as Swedish |
| `ListFormat`                               | 637 kB                | 3 kB                                                                             |
| `PluralRules`                              | 663 kB                | 3 kB                                                                             |
| `DisplayNames`                             | 781 kB                | 136 kB                                                                           |
| `NumberFormat` (with `PluralRules`)        | 933 kB                | 170 kB                                                                           |
| `RelativeTimeFormat` (with `NumberFormat`) | 982 kB                | 186 kB                                                                           |
| `DateTimeFormat` (with `NumberFormat`)     | 1.79 MB               | 722 kB                                                                           |
| All seven                                  | 2.15 MB               | About 850 kB                                                                     |

About 550 kB of each is the same code, `Intl.Locale` and `Intl.getCanonicalLocales` with their data, so two entries add less than their sum. If the bundle outgrows the `initial` [budget](/guide/building-for-production#budgets) in angular.json, raise it.

### Angular's pipes

Angular's `DatePipe`, `DecimalPipe`, `CurrencyPipe`, `PercentPipe` and `I18nPluralPipe` don't use `Intl`. They format with the locale data you register with [`registerLocaleData()`](https://angular.dev/api/common/registerLocaleData), for the `LOCALE_ID` that [`provideLocale()`](#set-up) sets. So they work without the `intl` option, and the option doesn't change them. For a locale, register Angular's data for the pipes, and list the locale in `i18n.locales` for code that calls `Intl`. Both follow the phone's language the same way.

### Without the Angular CLI

If you run RSpeedy yourself, or your build target in angular.json isn't AngularLynx's, pass the same list to the plugin in `lynx.config.ts`:

```typescript title="lynx.config.ts"
import { defineConfig, pluginAngularLynx } from '@blotch/angular-lynx-build';

export default defineConfig({
  plugins: [pluginAngularLynx({ intl: ['DisplayNames', 'NumberFormat'] })],
});
```
