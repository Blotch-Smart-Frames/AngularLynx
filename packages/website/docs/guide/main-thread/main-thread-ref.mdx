# `MainThreadRef`

A shared reference that can be read and written from both threads. Use it to pass state between main thread functions or to accumulate values across events (like a tap counter).

:::danger Escape Hatch — Not Standard Angular
Main thread scripts directly manipulate native elements, **bypassing Angular's signal-based change detection entirely**. This is analogous to direct DOM manipulation via `ElementRef.nativeElement` — something Angular [explicitly discourages](https://angular.dev/api/core/ElementRef). Only use when cross-thread latency is unacceptable (e.g., 60fps gesture tracking). Try standard Angular event bindings first.
:::

## Usage

```typescript
import { createMainThreadRef, mainThreadFn } from '@blotch/angular-lynx';
import type { MainThread } from '@blotch/angular-lynx';

const counter = createMainThreadRef(0); // [!code highlight]

const handleTap = mainThreadFn((event: MainThread.TouchEvent) => {
  counter.current++; // [!code highlight]
  const el = event.currentTarget;
  el.setStyleProperty('opacity', String(1 - counter.current * 0.1));
});
```

- `createMainThreadRef(initialValue)` creates a `MainThreadRef<T>`
- Access via `.current` (getter and setter)
- On the main thread, refs are stored in `globalThis.__workletRefMap` for worklet access
