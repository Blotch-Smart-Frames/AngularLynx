# Routing and navigation

Move between screens with Angular's Router, `<router-outlet>` and `routerLink`, as on the web. What differs: the URL lives in memory, a link is any element you tap, and the active link tells screen readers it's selected.

## Set up the router

Import `provideRouter()` from `@blotch/angular-lynx` instead of `@angular/router`. `ng add @blotch/angular-lynx` sets this up for you.

```typescript title="src/app/app.config.ts"
import {
  type ApplicationConfig,
  provideZonelessChangeDetection,
} from '@angular/core';
import { provideRenderer, provideRouter } from '@blotch/angular-lynx'; // [!code highlight]
import { routes } from './app.routes';

export const appConfig: ApplicationConfig = {
  providers: [
    provideZonelessChangeDetection(),
    provideRenderer(),
    provideRouter(routes), // [!code highlight]
  ],
};
```

```typescript title="src/app/app.routes.ts"
import type { Routes } from '@angular/router';
import { Home } from './home/home';
import { Settings } from './settings/settings';

export const routes: Routes = [
  { path: '', pathMatch: 'full', redirectTo: 'home' }, // [!code highlight]
  { path: 'home', component: Home },
  { path: 'settings', component: Settings },
];
```

- **Give the empty path `''` a route.** The app always starts at `/`, and there's no URL bar to start anywhere else. Without an `''` route, the first screen is blank.
- **`provideRouter()` takes the usual router features** as extra arguments, such as `withComponentInputBinding()`.

## Navigate between screens

```typescript title="src/app/app.ts"
import { Component } from '@angular/core';
import { RouterLink, RouterLinkActive, RouterOutlet } from '@angular/router';
import { LYNX_ELEMENTS } from '@blotch/angular-lynx';

@Component({
  selector: 'app-root',
  imports: [LYNX_ELEMENTS, RouterOutlet, RouterLink, RouterLinkActive],
  template: `
    <view class="flex flex-row">
      <view class="p-3" routerLink="/home" routerLinkActive="bg-accent">
        <text>Home</text>
      </view>
      <view class="p-3" routerLink="/settings" routerLinkActive="bg-accent">
        <text>Settings</text>
      </view>
    </view>
    <router-outlet />
  `,
})
export class App {}
```

- **`routerLink` and `routerLinkActive` are Angular's own,** from `@angular/router`. A tap on the element navigates: `RouterLink` listens for `click`, and AngularLynx hands it the tap, as [Lynx for Web](/guide/glossary#web-preview) does.
- **Put `routerLink` on any element**, usually the `<view>` around a label. An `<a routerLink>` works too: it renders as a `<text>` (see [HTML tags](/guide/elements/#html-tags)). Its inputs work as on the web, such as `queryParams`, `replaceUrl` and `state`. There's no `href` to show.
- **`routerLinkActive` adds its classes while the link's route is active.** For styling a class can't do, read its state: `#link="routerLinkActive"`, then `link.isActive`.
- **The active link is selected for screen readers.** While its route is active, `LYNX_ELEMENTS` adds `selected` to the element's `accessibility-traits`, after any traits of its own, and takes it away again after. iOS announces it as selected. Android has no selected trait, so there the element keeps its own traits.

:::tip
For tabs along the bottom of the screen, the [Tab Bar](/dolan/tab-bar) component does all of this: `npx @blotch/dolan add tab-bar`. The [Dock](/dolan/dock) is the same as a floating Liquid Glass bar.
:::

### Navigate from code

```typescript title="src/app/order-row.ts"
import { Component, inject } from '@angular/core';
import { Router } from '@angular/router';
import { LYNX_ELEMENTS } from '@blotch/angular-lynx';

@Component({
  selector: 'app-order-row',
  imports: [LYNX_ELEMENTS],
  template: `
    <view (bindtap)="open()">
      <text>Order #1042</text>
    </view>
  `,
})
export class OrderRow {
  readonly #router = inject(Router);

  open(): void {
    this.#router.navigate(['/orders', 1042]);
  }
}
```

- **Call `navigate()` or `navigateByUrl()` straight from a handler**, as on the web.
- **Failed navigations don't throw.** `navigate()` resolves to `false`, for example for a path with no route. Watch `Router.events` for `NavigationError` to find out why.

## Go back

Use `Location.back()` from `@angular/common`:

```typescript title="src/app/details/details.ts"
import { Location } from '@angular/common';
import { Component, inject } from '@angular/core';
import { LYNX_ELEMENTS } from '@blotch/angular-lynx';

@Component({
  selector: 'app-details',
  imports: [LYNX_ELEMENTS],
  template: ` <view (bindtap)="back()"><text>Back</text></view> `,
})
export class Details {
  readonly #location = inject(Location);

  back(): void {
    this.#location.back(); // [!code highlight]
  }
}
```

- **`Location.back()` and `Location.forward()`** move through the router's in-memory history.
- **`history.back()` does nothing** on a device, because there's no browser history.
- **The Android back button goes back a screen** in an app built with `ng build --platform android`. The router handles it like the browser's back button on the web, so guards such as `canDeactivate` still run. On the first screen, it leaves the app.
- **For a Back button in a top bar**, use the [Navigation Bar](/dolan/navigation-bar): it shows its Back button only while there's a screen to go back to, and calls `Location.back()`.

## Slide screens in and out, as a native app does

`<router-outlet>` swaps screens at once. Put `<lynx-stack-outlet>` in its place to move between them as iOS and Android apps do: a screen you open slides in over the last one, Back slides it away, and a finger can drag it back.

<Go example="stack-navigation" defaultFile="src/app/app.ts" />

```typescript title="src/app/app.ts"
import { Component } from '@angular/core';
import { LYNX_ELEMENTS, LynxStackOutlet } from '@blotch/angular-lynx'; // [!code highlight]

@Component({
  selector: 'app-root',
  imports: [LYNX_ELEMENTS, LynxStackOutlet], // [!code highlight]
  template: `
    <view class="flex h-full flex-col bg-background">
      <lynx-stack-outlet />
      <!-- [!code highlight] -->
    </view>
  `,
})
export class App {}
```

- **It's a router outlet.** It takes `<router-outlet>`'s inputs and outputs (`name`, `routerOutletData`, `(activate)`, `(deactivate)`), works with child routes, guards, resolvers, lazy routes and `withComponentInputBinding()`, and goes back through the router, so `canDeactivate` runs on a swipe too.
- **On iOS, it moves as UIKit's navigation controller does on iOS 26 and later:** the new screen slides in from the right with the display's rounded corners, over the last one, which slides a third of the way left and dims. The timing is fitted to iOS 27's own.
- **On Android, it moves as Android's activities do:** the new screen slides in a little way and fades in. A drag shrinks the screen with rounded corners, as Android's predictive back does.
- **Swipe back from the left edge, or from anywhere on the screen,** as on iOS 26. Inside something that scrolls sideways itself (a horizontal `<scroll-view>`, a `<list>`, a `<viewpager>`), only the edge swipes, so the scroller keeps its own swipes. A screen goes back if you let go past the middle or flick it.
- **Screens under the top one stay alive,** as a navigation controller's do. Back finds a screen as you left it, scrolled where you left it, with its state. To pause work while a screen is covered, inject `LynxStackPage` and read its `active()` signal.
- **Only the corners in the screen's corners round.** A screen rounds its corners as it moves to look like the screen it fills, so an outlet under an app bar or over a tab bar moves its screens with square corners where the bar meets them, as iOS and Android do. The outlet's box is measured against the LynxView, which an app fills the screen with.
- **Each screen is drawn on the theme's background** (`var(--background)`, white without the `@blotch/ui` theme), so the one under it doesn't show through. Give `pageClass` a class with another background for something else: `<lynx-stack-outlet pageClass="bg-card" />`.

### Which way a screen moves

The stack follows the URL, as a navigation controller follows the screens of an app:

| You go to                                                    | The stack                                    |
| ------------------------------------------------------------ | -------------------------------------------- |
| A deeper URL, `/notes/3` from `/notes`                       | Pushes it: it slides in from the right       |
| A URL in the stack, by Back, a swipe or a `routerLink` to it | Pops back to it: the screens above slide off |
| A URL the top one's is under, `/notes` from `/notes/3`       | Slides it in from behind, as a pop           |
| A URL at the same depth, `/settings` from `/home`            | Swaps to it at once, as a tab bar does       |
| Any URL with `replaceUrl: true`                              | Swaps the top screen at once                 |

So a back button made of a `routerLink` to the screen it came from slides back, and a tab bar beside the outlet switches tabs without a slide. When a screen should move otherwise, say so in the navigation's `info`, which Angular keeps for that navigation alone:

```html
<!-- A same-depth link that should still slide in -->
<view routerLink="/post/5" [info]="{ stack: 'push' }"><text>Post</text></view>
```

```typescript
router.navigate(['/home'], { info: { stack: 'root' } }); // a new stack, no slide
```

`'push'` slides a screen in, `'pop'` slides back to it, and `'root'` starts a new stack without a slide. The type is `StackNavigationInfo`.

### Choose the motion

`animation` picks it: `'ios'`, `'material'`, or `'none'`, which swaps screens at once and turns the swipe off. By default it's Material on Android and iOS everywhere else, the [web preview](/guide/glossary#web-preview) included. Turn only the swipe off with `[swipeBack]="false"`.

While Reduce Motion is on, a push or a pop cross-fades instead of sliding, as iOS's does. A drag still moves the screen with the finger.

### Good to know

- **A screen's own route stays its own.** Coming back to a screen, the router activates its route again. The screen's `ActivatedRoute` follows it, and its observables emit only what changed.
- **Angular reuses a component when only the params change,** as on the web: `/notes/1` to `/notes/2` updates the note in place rather than pushing a screen. Read params reactively (see [Read route parameters](#read-route-parameters)).
- **The [Navigation Bar](/dolan/navigation-bar) and the [Toolbar](/dolan/toolbar) keep their state per screen,** so each screen in the stack has its own large title and scroll edge. A bar of your own does the same with `injectBarState()`.
- **In Lynx Explorer, the left edge is Explorer's:** its own back gesture takes swipes from the edge. Swipe from inside the screen there. Apps built with `ng build --platform` have no such gesture.

## Read route parameters

Turn on `withComponentInputBinding()` to receive route parameters as inputs:

```typescript title="src/app/app.config.ts"
import {
  type ApplicationConfig,
  provideZonelessChangeDetection,
} from '@angular/core';
import { withComponentInputBinding } from '@angular/router';
import { provideRenderer, provideRouter } from '@blotch/angular-lynx';
import { routes } from './app.routes';

export const appConfig: ApplicationConfig = {
  providers: [
    provideZonelessChangeDetection(),
    provideRenderer(),
    provideRouter(routes, withComponentInputBinding()), // [!code highlight]
  ],
};
```

```typescript title="src/app/profile/profile.ts"
import { Component, input } from '@angular/core';
import { LYNX_ELEMENTS } from '@blotch/angular-lynx';

@Component({
  selector: 'app-profile',
  imports: [LYNX_ELEMENTS],
  template: `<text>Profile {{ id() }}</text>`,
})
export class Profile {
  readonly id = input.required<string>(); // from the `profile/:id` route
}
```

Read parameters reactively, through an input or `ActivatedRoute.paramMap`, rather than once in `ngOnInit`. `/profile/1` and `/profile/2` share one component instance (see [Good to know](#good-to-know)).

## Lazy-loaded routes

`loadComponent` works:

```typescript title="src/app/app.routes.ts"
import type { Routes } from '@angular/router';

export const routes: Routes = [
  { path: '', pathMatch: 'full', redirectTo: 'home' },
  {
    path: 'home',
    loadComponent: () => import('./home/home').then((m) => m.Home),
  },
];
```

It doesn't split your code, though. The build keeps every route's code in the [bundle](/guide/glossary#bundle), so nothing downloads when the user navigates.

## Differences from web Angular

| Feature      | Web Angular                                 | AngularLynx                            |
| ------------ | ------------------------------------------- | -------------------------------------- |
| URL          | Shown in the address bar                    | Kept in memory, never shown            |
| Starting URL | Any URL the browser opens                   | Always `/`                             |
| Links        | `<a routerLink>`                            | `routerLink` on any element, `<a>` too |
| Active link  | `aria-current` with `ariaCurrentWhenActive` | The `selected` accessibility trait     |
| Going back   | Browser back button, `history.back()`       | Android back button, `Location.back()` |
| Transitions  | `withViewTransitions()`                     | `<lynx-stack-outlet>`, with swipe back |
| Lazy routes  | Separate files, downloaded on demand        | Part of the bundle                     |

## Good to know

Leaving a route destroys its component, as on the web, so `ngOnDestroy` runs and its state is gone when you come back. `<lynx-stack-outlet>` keeps the screens under the top one alive until you go back past them. To keep every route view alive instead, provide [`LynxRouteReuseStrategy`](/api/angular-lynx/routing#lynxroutereusestrategy). Its views stay in memory, with their timers and subscriptions running, until the app closes.
