# Routing and navigation

Move between screens with Angular's Router, `<router-outlet>` and `routerLink`, as on the web. What differs: the URL lives in memory, a link is any element you tap rather than an `<a>`, and the active link tells screen readers it's selected.

## Set up the router

Import `provideRouter()` from `@blotch/angular-lynx` instead of `@angular/router`. `ng add @blotch/angular-lynx` sets this up for you.

```typescript title="src/app/app.config.ts"
import {
  type ApplicationConfig,
  provideZonelessChangeDetection,
} from '@angular/core';
import { provideRenderer, provideRouter } from '@blotch/angular-lynx'; // [!code highlight]
import { routes } from './app.routes';

export const appConfig: ApplicationConfig = {
  providers: [
    provideZonelessChangeDetection(),
    provideRenderer(),
    provideRouter(routes), // [!code highlight]
  ],
};
```

```typescript title="src/app/app.routes.ts"
import type { Routes } from '@angular/router';
import { Home } from './home/home';
import { Settings } from './settings/settings';

export const routes: Routes = [
  { path: '', pathMatch: 'full', redirectTo: 'home' }, // [!code highlight]
  { path: 'home', component: Home },
  { path: 'settings', component: Settings },
];
```

- **Give the empty path `''` a route.** The app always starts at `/`, and there's no URL bar to start anywhere else. Without an `''` route, the first screen is blank.
- **`provideRouter()` takes the usual router features** as extra arguments, such as `withComponentInputBinding()`.

## Navigate between screens

```typescript title="src/app/app.ts"
import { Component } from '@angular/core';
import { RouterLink, RouterLinkActive, RouterOutlet } from '@angular/router';
import { LYNX_ELEMENTS } from '@blotch/angular-lynx';

@Component({
  selector: 'app-root',
  imports: [LYNX_ELEMENTS, RouterOutlet, RouterLink, RouterLinkActive],
  template: `
    <view class="flex flex-row">
      <view class="p-3" routerLink="/home" routerLinkActive="bg-accent">
        <text>Home</text>
      </view>
      <view class="p-3" routerLink="/settings" routerLinkActive="bg-accent">
        <text>Settings</text>
      </view>
    </view>
    <router-outlet />
  `,
})
export class App {}
```

- **`routerLink` and `routerLinkActive` are Angular's own,** from `@angular/router`. A tap on the element navigates: `RouterLink` listens for `click`, and AngularLynx hands it the tap, as [Lynx for Web](/guide/glossary#web-preview) does.
- **Put `routerLink` on any element**, usually the `<view>` around a label. Its inputs work as on the web, such as `queryParams`, `replaceUrl` and `state`. There's no `href` to show, as on any element that isn't an `<a>`.
- **`routerLinkActive` adds its classes while the link's route is active.** For styling a class can't do, read its state: `#link="routerLinkActive"`, then `link.isActive`.
- **The active link is selected for screen readers.** While its route is active, `LYNX_ELEMENTS` adds `selected` to the element's `accessibility-traits`, after any traits of its own, and takes it away again after. iOS announces it as selected. Android has no selected trait, so there the element keeps its own traits.

:::tip
For tabs along the bottom of the screen, the [Tab Bar](/dolan/tab-bar) component does all of this: `npx @blotch/dolan add tab-bar`.
:::

### Navigate from code

```typescript title="src/app/order-row.ts"
import { Component, inject } from '@angular/core';
import { Router } from '@angular/router';
import { LYNX_ELEMENTS } from '@blotch/angular-lynx';

@Component({
  selector: 'app-order-row',
  imports: [LYNX_ELEMENTS],
  template: `
    <view (bindtap)="open()">
      <text>Order #1042</text>
    </view>
  `,
})
export class OrderRow {
  readonly #router = inject(Router);

  open(): void {
    this.#router.navigate(['/orders', 1042]);
  }
}
```

- **Call `navigate()` or `navigateByUrl()` straight from a handler**, as on the web.
- **Failed navigations don't throw.** `navigate()` resolves to `false`, for example for a path with no route. Watch `Router.events` for `NavigationError` to find out why.

## Go back

Use `Location.back()` from `@angular/common`:

```typescript title="src/app/details/details.ts"
import { Location } from '@angular/common';
import { Component, inject } from '@angular/core';
import { LYNX_ELEMENTS } from '@blotch/angular-lynx';

@Component({
  selector: 'app-details',
  imports: [LYNX_ELEMENTS],
  template: ` <view (bindtap)="back()"><text>Back</text></view> `,
})
export class Details {
  readonly #location = inject(Location);

  back(): void {
    this.#location.back(); // [!code highlight]
  }
}
```

- **`Location.back()` and `Location.forward()`** move through the router's in-memory history.
- **`history.back()` does nothing** on a device, because there's no browser history.
- **The Android back button goes back a screen** in an app built with `ng build --platform android`. The router handles it like the browser's back button on the web, so guards such as `canDeactivate` still run. On the first screen, it leaves the app.

## Read route parameters

Turn on `withComponentInputBinding()` to receive route parameters as inputs:

```typescript title="src/app/app.config.ts"
import {
  type ApplicationConfig,
  provideZonelessChangeDetection,
} from '@angular/core';
import { withComponentInputBinding } from '@angular/router';
import { provideRenderer, provideRouter } from '@blotch/angular-lynx';
import { routes } from './app.routes';

export const appConfig: ApplicationConfig = {
  providers: [
    provideZonelessChangeDetection(),
    provideRenderer(),
    provideRouter(routes, withComponentInputBinding()), // [!code highlight]
  ],
};
```

```typescript title="src/app/profile/profile.ts"
import { Component, input } from '@angular/core';
import { LYNX_ELEMENTS } from '@blotch/angular-lynx';

@Component({
  selector: 'app-profile',
  imports: [LYNX_ELEMENTS],
  template: `<text>Profile {{ id() }}</text>`,
})
export class Profile {
  readonly id = input.required<string>(); // from the `profile/:id` route
}
```

Read parameters reactively, through an input or `ActivatedRoute.paramMap`, rather than once in `ngOnInit`. `/profile/1` and `/profile/2` share one component instance (see [Good to know](#good-to-know)).

## Lazy-loaded routes

`loadComponent` works:

```typescript title="src/app/app.routes.ts"
import type { Routes } from '@angular/router';

export const routes: Routes = [
  { path: '', pathMatch: 'full', redirectTo: 'home' },
  {
    path: 'home',
    loadComponent: () => import('./home/home').then((m) => m.Home),
  },
];
```

It doesn't split your code, though. The build keeps every route's code in the [bundle](/guide/glossary#bundle), so nothing downloads when the user navigates.

## Differences from web Angular

| Feature      | Web Angular                                 | AngularLynx                            |
| ------------ | ------------------------------------------- | -------------------------------------- |
| URL          | Shown in the address bar                    | Kept in memory, never shown            |
| Starting URL | Any URL the browser opens                   | Always `/`                             |
| Links        | `<a routerLink>`                            | `routerLink` on any element            |
| Active link  | `aria-current` with `ariaCurrentWhenActive` | The `selected` accessibility trait     |
| Going back   | Browser back button, `history.back()`       | Android back button, `Location.back()` |
| Lazy routes  | Separate files, downloaded on demand        | Part of the bundle                     |

## Good to know

Leaving a route destroys its component, as on the web, so `ngOnDestroy` runs and its state is gone when you come back. To keep route views alive instead, provide [`LynxRouteReuseStrategy`](/api/angular-lynx/routing#lynxroutereusestrategy). Its views stay in memory, with their timers and subscriptions running, until the app closes.
