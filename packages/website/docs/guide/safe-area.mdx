# Safe area

Keep content clear of the notch, the status bar and the home indicator. Lynx reads the same `env(safe-area-inset-*)` values that iOS Safari does.

The **safe area** is the part of the screen that hardware and system bars don't cover. On a recent iPhone, the notch or Dynamic Island covers the top edge, and the home indicator (the bar you swipe up) covers the bottom. On the web, a page with `viewport-fit=cover` pads itself with `env(safe-area-inset-top)` and its siblings. Lynx supports the same four values.

## Pad with `env()`

```css
.screen {
  padding-top: env(safe-area-inset-top);
  padding-bottom: env(safe-area-inset-bottom);
}

.tab-bar {
  /* a 56px bar, plus room for the home indicator */
  height: calc(56px + env(safe-area-inset-bottom));
  padding-bottom: env(safe-area-inset-bottom);
}
```

- **There are four values:** `safe-area-inset-top`, `safe-area-inset-right`, `safe-area-inset-bottom` and `safe-area-inset-left`.
- **They work inside `calc()`**, as in `.tab-bar` above.
- **Where no inset is known, the value is 0.** The padding collapses instead of breaking the layout.

## Where the insets come from

| Where the app runs                                       | What `env()` gives                                                                                      |
| -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| Apps from `ng build --platform`                          | The window's insets, on iOS and Android, following rotation. 0 on every side with `"edgeToEdge": false` |
| [Lynx Explorer](/guide/glossary#lynx-explorer) on iPhone | The window's insets, wherever your page sits on screen                                                  |
| Your own iOS app                                         | The window's insets when the LynxView was created, or the insets your app sends (see below)             |
| Your own Android app                                     | 0 on every side, unless your app sends the insets (see below): Lynx doesn't read them on Android        |
| [Web preview](/guide/glossary#web-preview)               | 0                                                                                                       |

### The apps `ng build --platform` makes

They draw the page over the whole screen, under the status bar and the home indicator, as Safari does for a page with `viewport-fit=cover`. A scroll view's content scrolls under the status bar, a header image or a map reaches the top edge, and a bar that floats at the bottom, such as the [dock](/dolan/dock), floats over a page that runs to the bottom of the screen. Pad the content, not the screen:

```angular-html
<scroll-view scroll-orientation="vertical" class="flex-1">
  <view class="flex flex-col px-4 pt-safe-3 pb-safe-24">
    <!-- the first row starts below the status bar, and scrolls under it -->
  </view>
</scroll-view>
```

`env()` follows the insets when they change: when the phone rotates, and on Android when the keyboard opens. The keyboard pushes the page up so the input you type into stays above it, and the bottom inset is 0 while it's open, because the page then ends above the navigation bar.

To keep the page inside the safe area instead, set `edgeToEdge` to `false` in the build target's options in `angular.json`. The page then starts below the status bar and ends above the home indicator, and `env()` is 0 on every side:

```jsonc title="angular.json"
"options": {
  "appName": "Example",
  "appId": "com.example.app",
  "edgeToEdge": false
}
```

The apps send the insets as numbers too, with `isNotchScreen` and `edgeToEdge`: see [What the generated apps pass](/guide/embedding/host-data#what-the-generated-apps-pass).

Lynx's own `env()` can't follow the window there: on Android it's always 0, and on iOS each element reads it once. So the build points each `env(safe-area-inset-*)` in a stylesheet at a CSS variable the page sets from the app's insets, and the runtime writes the insets into inline styles and style bindings itself. One place it doesn't reach is a CSS variable defined in a stylesheet: in `--gap: calc(env(safe-area-inset-top) + 8px)`, `env()` stays Lynx's own, 0 in these apps. Write `env()` where the variable is read instead, as in `padding-top: calc(env(safe-area-inset-top) + 8px)`.

### Your own app

On iOS, Lynx reads the window's insets each time a LynxView is created, and never again: a LynxView created before its window is shown reads 0, and one on screen keeps the insets it read when the phone rotates.

To have `env()` follow the window as the generated apps do, send the same global props they send: `edgeToEdge: true` with `safeAreaTop`, `safeAreaRight`, `safeAreaBottom` and `safeAreaLeft`, the part of the LynxView the system bars cover, again whenever it changes. This works on Android too.

## Tailwind utilities

The [UI components](/dolan/)' theme adds padding utilities built on `env()`: its `tailwind.css` for Tailwind 4, or its Tailwind plugin, `blotchPlugin`, for Tailwind 3. `npx @blotch/dolan init` copies the one your app needs into your project.

```angular-html
<!-- padding equal to the inset -->
<view class="pb-safe">...</view>

<!-- 1rem of padding plus the inset: calc(1rem + env(safe-area-inset-bottom)) -->
<view class="pb-safe-4">...</view>
```

| Class                                   | Padding                          |
| --------------------------------------- | -------------------------------- |
| `pt-safe` `pr-safe` `pb-safe` `pl-safe` | The inset on one side            |
| `px-safe` `py-safe`                     | The insets on two opposite sides |
| `p-safe`                                | The insets on all four sides     |
| `pt-safe-<n>` `pb-safe-<n>` and so on   | A spacing value plus the inset   |

The `<n>` takes any value from your spacing scale, as `p-<n>` does: `pb-safe-8`, `pt-safe-2`.

## Check for a notch in TypeScript

Prefer CSS: `env()` adapts to every device without code. For logic CSS can't express, inject `LynxSafeArea`.

```typescript title="src/app/header.ts"
import { Component, inject } from '@angular/core';
import { LYNX_ELEMENTS, LynxSafeArea } from '@blotch/angular-lynx';

@Component({
  selector: 'app-header',
  imports: [LYNX_ELEMENTS],
  template: `
    <view
      class="app-header"
      [class.app-header-notch]="safeArea.isNotchScreen()"
    >
      <text>Inbox</text>
    </view>
  `,
  styles: `
    .app-header {
      padding: 12px 16px;
    }
    .app-header-notch {
      padding-top: calc(12px + env(safe-area-inset-top));
    }
  `,
})
export class Header {
  protected readonly safeArea = inject(LynxSafeArea);
}
```

- **`isNotchScreen()`** is a signal that's `true` when the device has a notch or camera cutout. It comes from the [host app](/guide/glossary#host-app) (the native app that runs your bundle). Lynx Explorer and the apps that `ng build --platform` makes pass it.
- **`platform`** is the operating system. On phones it's `'iOS'`, `'Android'` or `'Harmony'`, which is Huawei's HarmonyOS.
- **`SAFE_AREA_INSET_TOP`**, `SAFE_AREA_INSET_RIGHT`, `SAFE_AREA_INSET_BOTTOM` and `SAFE_AREA_INSET_LEFT` are the `env()` strings, such as `'env(safe-area-inset-top)'`, for building styles in TypeScript.
