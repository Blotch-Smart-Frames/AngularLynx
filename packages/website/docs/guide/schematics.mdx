# Schematics

The `@blotch/angular-lynx` package includes Angular CLI schematics to automate project setup and code generation.

## `ng add` — Project Setup

Transforms an existing Angular project into a Lynx-native application in one command:

```bash
ng add @blotch/angular-lynx
```

This rewrites your project's entry point, app config, and root component for Lynx, points the Angular CLI at the AngularLynx builders and schematics, installs the build tooling, and optionally adds Tailwind CSS. Everything else stays as `ng new` left it: the build config is in `angular.json`, as in any Angular app.

**What it does:**

- Replaces `main.ts` with `bootstrapApplication` from `@blotch/angular-lynx`
- Rewrites `app.config.ts` with `provideRenderer()` and `provideZonelessChangeDetection()`
- Replaces the root component with one whose inline template uses Lynx elements (`<view>`, `<text>`), and removes its `.html`, `.css` and spec files
- Points `ng build`, `ng serve` and `ng test` at the AngularLynx builders, keeping `ng new`'s configurations and options
- Puts `@blotch/angular-lynx` first in `cli.schematicCollections`, so `ng generate component` makes Lynx components
- Raises `ng new`'s `initial` budget (500 kB warning, 1 MB error) to 2 MB and 5 MB: a Lynx bundle holds Angular twice, once for each of Lynx's threads, so a new app's bundle is already about 1 MB
- Adds `src/rspeedy-env.d.ts`, the types for asset and CSS module imports
- Installs `@blotch/angular-lynx-build`, the builders, which bring rspeedy, the AngularLynx rsbuild plugin and the native app builder with them
- Optionally sets up Tailwind CSS (prompted interactively)

It doesn't create a `lynx.config.ts`: the builders take the entry point from `angular.json`. Add one only to [customize rspeedy](/guide/building-for-production#customize-rspeedy).

**Options:**

| Option       | Type      | Default         | Description                    |
| ------------ | --------- | --------------- | ------------------------------ |
| `--project`  | `string`  | default project | Target project in angular.json |
| `--tailwind` | `boolean` | `true`          | Whether to add Tailwind CSS    |

## `component` — Generate Components

After `ng add`, Angular's own command generates Lynx components:

```bash
ng generate component my-feature   # or: ng g c my-feature
```

`ng add` puts `@blotch/angular-lynx` first in `angular.json`'s `cli.schematicCollections`, so `ng generate component` runs this schematic. Every other schematic (`service`, `pipe`, `guard`, `directive`, ...) still comes from Angular's collection, which is listed after it. Without that setting, call it by name: `ng generate @blotch/angular-lynx:component my-feature`.

It runs Angular's own component schematic, so the files, names and options are the ones you know, and `angular.json`'s defaults for `@schematics/angular:component` (such as `style: scss`) apply. Then it makes the component a Lynx one:

- The placeholder `<p>` becomes Lynx elements: `<view><text>my-feature works!</text></view>`
- The component imports `LYNX_ELEMENTS`, so its template type-checks in the editor and under `ng test`
- With [`@blotch/angular-lynx-testing-library`](/guide/testing) installed, Angular's `TestBed` spec is replaced with a `*.test.ts` that renders the component on Lynx. Without it, Angular's spec stays; `ng test` runs both kinds.

**Generated files** (default, with the testing library installed):

```
src/app/my-feature/
  my-feature.ts       # Component, importing LYNX_ELEMENTS
  my-feature.html     # Lynx template
  my-feature.css      # Styles
  my-feature.test.ts  # Test using render()
```

**Example output:**

```typescript title="my-feature.ts"
import { Component } from '@angular/core';
import { LYNX_ELEMENTS } from '@blotch/angular-lynx';

@Component({
  imports: [LYNX_ELEMENTS],
  selector: 'app-my-feature',
  styleUrl: './my-feature.css',
  templateUrl: './my-feature.html',
})
export class MyFeature {}
```

```html title="my-feature.html"
<view>
  <text>my-feature works!</text>
</view>
```

```typescript title="my-feature.test.ts"
import { render } from '@blotch/angular-lynx-testing-library';
import { describe, expect, it } from 'vitest';

import { MyFeature } from './my-feature';

describe('MyFeature', () => {
  it('should render', async () => {
    const { getByText } = await render(MyFeature);
    expect(getByText('my-feature works!')).toBeTruthy();
  });
});
```

Angular 22 components use `OnPush` change detection by default, which zoneless Lynx apps need.

**Options:** all of [Angular's component options](https://angular.dev/cli/generate/component), e.g. `--inline-template` (`-t`), `--inline-style` (`-s`), `--style`, `--skip-tests`, `--flat`, `--type`, `--export-default`, `--selector`, `--change-detection`.

**Nested paths:**

```bash
# Creates src/app/pages/dashboard/dashboard.ts
ng generate component pages/dashboard
```

## `add-tailwind` — Add Tailwind CSS

Adds [Tailwind CSS](/guide/tailwindcss) with the Lynx preset to an existing project:

```bash
ng generate @blotch/angular-lynx:add-tailwind
```

**What it does:**

- Creates `tailwind.config.ts` with `@lynx-js/tailwind-preset` and `content: ['./src/**/*.ts']`
- Updates the global stylesheet (`styles.css` or `styles.scss`) with Tailwind directives
- Installs `tailwindcss` and `@lynx-js/tailwind-preset` as devDependencies

**Options:**

| Option      | Type     | Default         | Description    |
| ----------- | -------- | --------------- | -------------- |
| `--project` | `string` | default project | Target project |

## `add-testing` — Add Testing Library

Adds the [AngularLynx Testing Library](/guide/testing) to an existing project:

```bash
ng generate @blotch/angular-lynx:add-testing
```

**What it does:**

- Installs `@blotch/angular-lynx-testing-library`, plus `vitest` and `jsdom` if the project doesn't have them (`ng new` adds both, and keeps its versions)
- Points the `test` target at `@blotch/angular-lynx-build:unit-test` if it isn't already (`ng add` does that for new projects)
- Sets the `test` script in `package.json` to `ng test`

`ng test` loads the library's setup itself whenever it's installed, so there's no Vitest config or setup file to add. Components generated from then on get a test that renders them on Lynx.

**Options:**

| Option      | Type     | Default         | Description    |
| ----------- | -------- | --------------- | -------------- |
| `--project` | `string` | default project | Target project |

## `add-i18n` — Add Internationalization

Adds [i18n support](/guide/i18n) with `@angular/localize` to an existing project:

```bash
ng generate @blotch/angular-lynx:add-i18n
```

**What it does:**

- Adds the `i18n` block to `angular.json` (`sourceLocale: 'en-US'`)
- Appends `@angular/localize/init` to the `polyfills` array in `angular.json`
- Adds `@angular/localize` to `compilerOptions.types` in `tsconfig.app.json` so `$localize` is typed
- Registers `provideLocale()` as the first provider in `app.config.ts`
- Installs `@angular/localize` as a devDependency

**Options:**

| Option      | Type     | Default         | Description    |
| ----------- | -------- | --------------- | -------------- |
| `--project` | `string` | default project | Target project |

## `eject` — Own the Native Projects

Writes the iOS and Android projects that `ng build --platform` generates into `ios/` and `android/`, for native changes the builder options don't cover:

```bash
ng generate @blotch/angular-lynx:eject
```

`ng build --platform` then builds those folders as they are. This is one-way: the app identity options in `angular.json` stop applying to an ejected project, and keeping it current with Lynx, Xcode and Google Play becomes your job. See [Publishing your App](/guide/building-for-production#customize-the-native-project).

| Option       | Type                        | Default         | Description                    |
| ------------ | --------------------------- | --------------- | ------------------------------ |
| `--project`  | `string`                    | default project | Target project in angular.json |
| `--platform` | `ios` \| `android` \| `all` | `all`           | Which project to eject         |
