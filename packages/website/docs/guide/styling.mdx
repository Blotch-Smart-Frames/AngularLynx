# CSS on Lynx

Lynx draws your app with its own CSS engine, not a browser's. Most layout and visual CSS carries over, but some defaults differ and some features are missing. This page covers what trips up web developers, and what to write instead.

For every property and value Lynx accepts, see the [Lynx CSS reference](https://lynxjs.org/api/css/properties.html).

## At a glance

| On the web                                    | On Lynx                                                                 |
| --------------------------------------------- | ----------------------------------------------------------------------- |
| `:root`, `html`, `body`                       | [`page`](#the-root-is-page)                                             |
| `display: block` by default                   | `display: linear` (a vertical stack) by default. `flex` and `grid` work |
| `box-sizing: content-box`, collapsing margins | `border-box`, and margins never collapse                                |
| Text anywhere                                 | Text only inside `<text>`                                               |
| `color` and fonts inherit                     | [Nothing inherits](#inheritance), except into a nested `<text>`         |
| `1rem` is 16px                                | `1rem` is 14px                                                          |
| `overflow: auto` scrolls                      | Only `<scroll-view>` and `<list>` scroll                                |
| `position: fixed` pins to the viewport        | Positions against the `page`. Use `<overlay>` for floating UI           |
| `:hover`, `::before`, `@media`, `!important`  | [Not supported](#selectors-and-rules)                                   |
| `hsl(240 6% 10%)`                             | [Dropped silently](#colors). Write `hsl(240, 6%, 10%)` or `rgba()`      |

## The root is `page`

```css title="src/styles.css"
page {
  background-color: #ffffff;
  --brand: rgba(79, 70, 229, 1);
}
```

- [**`page`**](/guide/glossary#page) is the root [element](/guide/glossary#element) of every Lynx app. Its selector does the job of `:root` and `body`.
- `html` and `body` match nothing.
- Put app-wide CSS variables on `page`. Every element below it can read them.

## Layout

```css
.toolbar {
  display: flex;
  flex-direction: row;
  align-items: center;
  gap: 8px;
}
```

- **Elements stack vertically by default.** Lynx's default `display` is `linear`, which lays children out in a column. `flex` and `grid` work as on the web. `block`, `inline` and `inline-block` don't exist.
- **`flex-direction: row` needs `display: flex`.** On a linear element it does nothing. In Tailwind, write `flex flex-row`, not `flex-row` alone.
- **Children stretch across their parent.** A child with no width fills the parent's cross axis. Add `align-self: flex-start` (Tailwind `self-start`) to make a badge hug its content.
- **Boxes are `border-box`**, and **margins never collapse**: a 16px bottom margin above a 16px top margin makes 32px.
- **`min-width` and `min-height` default to 0**, not `auto`. A flex item can shrink below its content and clip its text. Set a `min-width` to stop it.
- **Every element is `position: relative`** by default, so `z-index` works on any element.
- **Siblings paint in source order.** A later sibling draws on top, even when an earlier one is `position: absolute`.
- **`position: fixed`** acts like `position: absolute` against the `page`. For floating UI such as menus, use [`<overlay>`](/guide/overlays).
- **`position: sticky`** works only inside a `<scroll-view>`.
- **`overflow` is `visible` or `hidden`.** A `<view>` never scrolls. Use [`<scroll-view>`](/api/elements/scroll-view) or [`<list>`](/api/elements/list).

[Elements and layout](/guide/elements/) covers which element to use for what.

## Text

```css
.summary {
  font-size: 15px;
  line-height: 22px;
  text-overflow: ellipsis;
}
```

```angular-html
<text class="summary" text-maxline="2">
  Your order left the warehouse this morning and arrives on Friday.
</text>
```

- **Text renders only inside [`<text>`](/api/elements/text).** Text placed directly in a `<view>` doesn't show.
- **Put text styles on the `<text>`.** A `color`, `font-size` or `line-height` on a `<view>` doesn't reach the text inside it (see [Inheritance](#inheritance)).
- **`line-height` works only on `<text>`.**
- **`white-space` is `normal` or `nowrap`.** There's no `pre`, so spaces and line breaks always collapse.
- **There's no `text-transform`**, so Tailwind's `uppercase` does nothing. Change the case in TypeScript.
- **There's no `text-align: justify`.**
- **Clamp lines with the `text-maxline` attribute**, as above, instead of `-webkit-line-clamp`. Pair it with `text-overflow: ellipsis`: without it, Android draws the extra lines past the box.

## Inheritance

```angular-html
<!-- color on the view doesn't reach the text -->
<view style="color: white">
  <text>Not white</text>
</view>

<!-- set it on the text itself -->
<view>
  <text style="color: white">White</text>
</view>
```

- **CSS properties don't inherit by default.** Each element gets only the rules that match it. Inheritance has a performance cost, so Lynx leaves it off.
- **A nested `<text>` is the exception.** An inner `<text>` takes its parent `<text>`'s `color` and `font-family`.
- **CSS variables always inherit**, as on the web. Set them on a parent and use `var()` anywhere below it.
- **There's no `inherit`, `initial` or `unset` keyword.**

To make text properties inherit as on the web, turn on `enableCSSInheritance` in a `lynx.config.ts` at the project root:

```typescript title="lynx.config.ts"
import { defineConfig, pluginAngularLynx } from '@blotch/angular-lynx-build';

export default defineConfig({
  plugins: [pluginAngularLynx({ enableCSSInheritance: true })],
});
```

Then `color`, `direction`, `font-family`, `font-size`, `font-style`, `font-weight`, `letter-spacing`, `line-height`, `text-align`, `text-decoration` and `text-shadow` inherit. To pick the list yourself, also pass `customCSSInheritanceList`. Both are in the plugin options on the [`@blotch/angular-lynx-build` page](/api/build/).

## Units

| Unit                  | On Lynx                                                      |
| --------------------- | ------------------------------------------------------------ |
| `px`                  | A device-independent pixel, as on the web                    |
| `rem`                 | 14px, Lynx's root font size. The default `font-size` is 14px |
| `rpx`                 | 1/750 of the screen width, so `750rpx` is always full width  |
| `%`, `em`, `vw`, `vh` | As on the web                                                |

- **`rem` is 14px, not 16px.** Rem-based sizes come out 12.5% smaller than in a browser. That includes Tailwind's scale: `h-11` is 38.5px. Use `px` where a size must line up with something exact.
- **Lengths need units.** Only `0` can go without one, and `margin: 5` is ignored. Times need units too: `0ms`, not `0`.
- **`calc()` and `env()` work. `min()`, `max()` and `clamp()` don't.**

## Colors

| Format                     | Example                     | Works |
| -------------------------- | --------------------------- | ----- |
| Hex                        | `#18181b`, `#ff000080`      | Yes   |
| Named                      | `red`, `transparent`        | Yes   |
| `rgb()` / `rgba()`, commas | `rgba(24, 24, 27, 0.5)`     | Yes   |
| `rgb()`, spaces            | `rgb(24 24 27 / 0.5)`       | Yes   |
| `hsl()` / `hsla()`, commas | `hsla(240, 5.9%, 10%, 0.5)` | Yes   |
| `hsl()`, spaces            | `hsl(240 5.9% 10% / 0.5)`   | No    |
| `currentColor`             |                             | No    |

- **Space-separated `hsl()` fails silently.** The element draws transparent, with no warning. Lynx's parser reads `hsl()` only in its comma form.
- **`currentColor` isn't supported.** Use the color itself, or a CSS variable.

### Theme colors in CSS variables

Store each color whole in a variable, then reference the variable directly:

```css title="src/styles.css"
page {
  --primary: rgba(24, 24, 27, 1);
  --primary-foreground: rgba(250, 250, 250, 1);
  --primary-subtle: rgba(24, 24, 27, 0.1);
}

.button {
  background-color: var(--primary);
}

.button-label {
  color: var(--primary-foreground);
}
```

- **Don't store raw channels** (`--primary: 240 5.9% 10%`) to wrap later in `hsl(var(--primary))`. That expands to the space-separated `hsl()` Lynx drops, which is why shadcn-style themes render blank.
- **For a translucent shade, add a variable of its own**, like `--primary-subtle`, or use channels in `rgba()`, below.
- **Set variables in a stylesheet or a static `style` attribute.** A `[style.--name]` binding doesn't reach the element yet.

### One color at any opacity

Keep a color's channels in a second variable, comma-separated, and wrap it in `rgba()`:

```css title="src/styles.css"
page {
  --primary: rgba(24, 24, 27, 1);
  --primary-rgb: 24, 24, 27;
}

.scrim {
  background-color: rgba(var(--primary-rgb), 0.5);
}
```

- Lynx replaces `var()` with the variable's text before it reads the color, so `24, 24, 27` fills three arguments, as in a browser.
- **Write the channels with commas** for `rgba()`. Space-separated channels work only in the `rgb(var(--x) / 0.5)` form.
- An undefined variable drops the whole value, and the element draws transparent.

The [UI components](/dolan/) theme works this way. Its Tailwind plugin turns `bg-primary/50` into `rgba(var(--primary-rgb), 0.5)`. See [Theming](/dolan/theming#opacity-modifiers).

## Selectors and rules

These work: type (`text`), class, ID, `*`, compound (`.a.b`), descendant, child (`>`), sibling (`+`, `~`), `:not()` and `:active` (while a finger is down). The at-rules are `@font-face`, `@keyframes` and `@import`.

| Missing                                                     | Use instead                                                               |
| ----------------------------------------------------------- | ------------------------------------------------------------------------- |
| `:hover`, `:focus`                                          | `:active`, or a class bound to a signal                                   |
| `::before`, `::after`                                       | A real element                                                            |
| `:first-child`, `:nth-child()` and other structural classes | A class bound to `@for`'s `$first`, `$last` or `$index`                   |
| Attribute selectors such as `[disabled]`                    | A class                                                                   |
| `:is()`, `:where()`, `:has()`                               | Separate selectors                                                        |
| `@media`, including `prefers-color-scheme`                  | Signals and class bindings. For themes, see [Dark mode](/guide/dark-mode) |
| `@supports`, `@layer`, `@container`, `@property`            | Nothing                                                                   |
| `!important`                                                | A more specific selector                                                  |
| `pointer-events`                                            | Leave it out: the build fails on it. The last sibling gets the taps       |
| `float`, `columns`                                          | Flexbox or grid                                                           |
| `outline`                                                   | `border`                                                                  |

**Descendant selectors don't re-match when a class changes.** By default, `.selected .label` applies only when classes are first set. Toggle a class on the element itself, or switch CSS variables, instead. The `enableCSSInvalidation` [plugin option](/api/build/) makes them re-match, at some cost in speed.

## Component styles

```typescript title="src/app/card/card.ts"
import { Component, input } from '@angular/core';
import { LYNX_ELEMENTS } from '@blotch/angular-lynx';

@Component({
  selector: 'app-card',
  imports: [LYNX_ELEMENTS],
  template: `<text class="title">{{ title() }}</text>`,
  styles: `
    :host {
      padding: 16px;
      border-radius: 12px;
    }
    .title {
      font-size: 18px;
    }
  `,
})
export class Card {
  readonly title = input.required<string>();
}
```

`styles` and `styleUrl` are scoped to the component, as in Angular on the web:

- **`ViewEncapsulation.Emulated`**, the default, applies a component's rules only to the elements in its own template. The `.title` rule above doesn't touch a `.title` in any other component.
- **`:host` styles the component's own element.** `:host(.active)` and `:host-context(.dark)` work too. A class set with `host: { class: '…' }` is on that element, so style it with `:host(.…)`.
- **`::ng-deep`** turns scoping off for the rest of the selector, to reach into child components. Angular deprecates it: prefer an input or a class on the child.
- **`ViewEncapsulation.None`** makes the component's rules apply app-wide.
- **`ViewEncapsulation.ShadowDom`** falls back to `None`, with a warning at build time and run time. Lynx has no shadow DOM.
- **A rule that depends on an ancestor's class**, such as `:host(.active) .title`, follows the rule above: toggling the class at runtime doesn't re-match it by default.
- **Component stylesheets are plain CSS.** A `.scss` or `.less` file in `styleUrl` isn't compiled.

Lynx's CSS engine can't match attribute selectors, so AngularLynx scopes with classes where the web uses attributes. In the element tree, a component's elements carry a `_ngcontent-<id>` class, and its host element a `_nghost-<id>` class.
